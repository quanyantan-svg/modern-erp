# 启明 ERP：基础资料与销售订单最小重构版

这是从方天云端 ERP B9V27 中提炼出的独立练习项目，覆盖：

```text
登录 → 用户/角色 → 客户 → 货品 → 销售订单 → 提交 → 审核/驳回 → 查看与追踪
```

它不会连接或修改原 ERP 数据库。第一次启动会自动创建本地 `data/erp.db`，并写入演示账号和基础资料。

## 技术栈

- 前端：React 19、Vite 7、原生 CSS
- 后端：Node.js 原生 HTTP API
- 数据库：Node.js 内置 SQLite
- 认证：随机 Bearer Token；数据库只保存 Token 哈希
- 密码：`scrypt` 加盐哈希
- 测试：Node.js 内置测试框架

需要 Node.js 22.13 或更高版本，推荐 Node.js 24。

## 快速运行

在本目录执行：

```powershell
corepack enable
pnpm install
pnpm build
pnpm start
```

然后打开：

```text
http://127.0.0.1:3001
```

本工作区已经完成依赖安装和前端构建，也可以直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start-local.ps1
```

开发模式：

```powershell
pnpm dev
```

开发页面为 `http://127.0.0.1:5173`，API 为 `http://127.0.0.1:3001`。

## 演示账号

| 账号 | 密码 | 角色 | 用途 |
|---|---|---|---|
| `sales` | `sales123` | 销售专员 | 维护客户、创建并提交订单 |
| `reviewer` | `review123` | 销售主管 | 审核或驳回待审核订单 |
| `admin` | `admin123` | 系统管理员 | 管理用户、角色和全部基础资料 |

推荐演示顺序：

1. 使用 `sales` 登录；
2. 新建销售订单并保存草稿；
3. 在订单列表中提交审核；
4. 退出并使用 `reviewer` 登录；
5. 在“订单审核”中查看订单，审核通过或填写原因后驳回；
6. 返回销售订单列表查看状态和完整操作记录。

系统内置一张 `SO-DEMO-001` 待审核订单，方便直接体验审核。

## 业务规则

- 订单至少包含一条明细，数量必须大于 0；
- 金额以后端重新计算为准，不能相信前端传入的合计；
- 只有草稿或已驳回订单可以修改和提交；
- 只有待审核订单可以审核或驳回；
- 制单人不能审核自己的订单；
- 审核订单不扣库存，后续“销售出货”才应扣库存；
- 所有创建、修改、提交、审核和驳回都会写入审计日志。

## 数据重置

需要恢复初始演示数据时，先停止服务，再执行：

```powershell
pnpm reset-data
```

下次启动会重新建立数据库。该命令只删除本项目 `data` 目录中的演示数据库。

## 自动化测试

```powershell
pnpm test
```

测试会在内存数据库中完成销售制单、提交、越权拦截、主管审核和操作记录验证，不会修改本地演示数据。

## 练习版边界

当前版本故意不包含销售出货、库存扣减、应收账款、复杂多级审批、多组织、多币种和原数据库迁移。这些属于下一阶段，不应在尚未验证基础流程前一次性加入。

演示账号使用公开弱密码，只能用于本机练习；生产部署前必须删除种子账号、使用 HTTPS、增加登录限流、密钥管理、数据库备份和完整安全测试。
