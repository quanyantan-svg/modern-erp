### 首期范围内的关键实现决定

1. **交期台账是交期容量的唯一权威来源。** 旧累计字段
   `purchase_order_delivery_schedules.received_quantity` 在首期**不由 WP-1
   写入**，也不作为容量输入 —— 这正是"避免旧累计字段和新 effect 台账双重
   扣减"的要求。
2. **交期消费 effect 在采购入库单创建时登记**（草稿即占用交期容量），取消
   草稿入库单时以**新的负向 effect** 冲销，原 effect 不被修改。
3. **转换产生草稿采购入库单**：库存 / 估值 / 财务效力仍在既有
   `POST /api/purchase-receipts/:id/confirm` 环节产生。原因是默认来料检验
   规则（`QCP-IN-GLOBAL`，`inspection_required=1`）要求入库单先存在并完成
   IQC 判定；因此"通知来源累计量"与"转换成功"同处一个事务（创建入库单 +
   累计 `converted_quantity`），"库存 / 估值效力"与"入库单确认"同处一个
   事务。
4. **由收料通知转换的采购入库单禁止 `PATCH` 修改**：其行携带不可变的通知
   来源行与交期预留，改写会破坏来源追溯与台账一致性。
5. **转换要求显式 `Idempotency-Key`**：同一通知可多次合法部分转换，幂等
   scope 固定为 `(RECEIPT_NOTICE_CONVERT, noticeId, idempotency_key)`；缺键
   400，不用默认键把两次不同的合法转换误判为重放。
6. **标准采购收料通知必须携带可证明的交期**（零交期 / 多交期未显式指定 →
   409 `RECEIPT_NOTICE_SCHEDULE_UNPROVEN`），这是已批准 Requirement
   `MC-REQ-02` 的明确后果：**没有交期的采购订单行无法创建收料通知**。
7. **直接 PO → 采购入库路径保持既有合法行为**：其草稿入库单不占用采购
   订单行容量（沿用既有口径），容量在确认时封顶；通知分配量则从通知创建起
   占用订单行容量，两者不重复扣减。
8. **既有回归测试的两处适配**（因上述合同变化，非为掩盖缺陷）：
   `server/procurement-receiving-returns.test.js` 与
   `server/out-final-acceptance.test.js` 的标准采购通知用例补建交期与订单行
   来源，断言内容未削弱。
