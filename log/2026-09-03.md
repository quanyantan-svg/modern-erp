**Goal**

完成 `v1.0.1-rc.3` 前最后有界稳定化：修复四类仓储物流单据的金额、草稿编辑、状态、库存与凭证一致性；修复盘点流程；收口重复收入确认、CLOSED 期间业务凭证与业务动作原子性；隐藏未完成的 AR/AP/收付款演示页。

**Canonical contracts**

- Logistics money: `unit_price_cents` / `amount_cents` / `total_cents` 为整数分；行金额由服务端按 quantity × unit price 计算，表头为行合计；客户端 total 不可注入。无来源订单/出入库单时，单价仍由用户显式输入，不静默回退为 0。
- Logistics status: `DRAFT / CONFIRMED / CANCELLED`。DRAFT 使用 PATCH 原位替换明细；CONFIRMED/CANCELLED 不可修改、重复确认或取消。
- Stock effects: Purchase Receipt IN, Sales Delivery OUT, Sales Return IN, Purchase Return OUT。确认事务写入可追踪 inventory transaction，重复确认不重复影响。
- Voucher integrity: 凭证借贷各自等于单据权威总额。销售订单 APPROVE 不产生收入凭证；销售出库 CONFIRM 是唯一收入确认点。
- Closed periods: `generateVoucher()` 集中拦截 CLOSED 期间；物流确认在同一 `BEGIN IMMEDIATE` 事务中先验期间，失败时单据、库存、流水和凭证均不变。
- Stocktake: `check_no` 非空、唯一且稳定；`DRAFT → SUBMITTED → APPROVED`；warehouse 创建/编辑/提交，admin 使用新注册的 `INVENTORY_CHECK_APPROVE` 审批，创建人不可自审。只在 APPROVED 时调整库存并写盘点流水。
- Deferred UI: AR/AP/Collections/Disbursements 不是当前支持面，从导航和页面装配移除；内部 API 代码保留。
