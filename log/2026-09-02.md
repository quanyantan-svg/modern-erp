# 2026-09-02 日志

## Phase E — Hotfix: Trial Balance Period & Subject Filter Fix (v0.9.5 candidate)

**Goal**

修复 Phase E production browser verification 阶段由用户在腾讯云生产环境确认的最后一个 accounting 报表 blocker:`会计凭证 → 试算平衡表 → 期间 2026-09` 显示完全空白,而同期 `利润表 / 资产负债表` 均正确。两个独立缺陷同时修复:`subject filter` 把所有 seed 科目都过滤掉了,以及 `endDate` 在 UTC+8 时区 off-by-one。严格 scope:不动 schema、不改 reporting 公式语义、不改 voucher state machine、不改其他报表。

**Root Cause**

复现路径(临时脚本 `scripts/_test_trial_balance.mjs`,已删除):会计 → 新建 SMOKE-E01 / SMOKE-E02 → 提交 → admin 审核 → 过账 → 查询 `/api/reports/trial-balance?period=2026-09` → 返回 `trialBalance: []`(完全空)。同期 Income Statement 返回 `revenue=1000000 / expense=400000 / profit=600000`,Balance Sheet 返回 `equationValid=true`。两个独立的 bug 在 trial balance 内叠加:

1. **Subject filter 排除了所有 seed 科目**。`server/app.js:1817` 的 `getTrialBalance` 用 `SELECT … FROM accounting_subjects WHERE active = 1 AND parent_id IS NOT NULL`,而 `server/db.js:1139-1148` 的 seed 把 7 个科目(`1001 / 1002 / 1122 / 1405 / 2202 / 6001 / 6401`)全部不设置 `parent_id`(`parent_id = NULL`)。`parent_id IS NOT NULL` 把所有种子行都过滤掉,subjects 数组为空,整个 trial balance 当然空。同期 Income Statement / Balance Sheet **不**过滤 `parent_id`,所以它们显示正确。
2. **`endDate` 在 UTC+8 off-by-one**。原代码 `endDate = new Date(y, m, 0).toISOString().slice(0, 10)` —— 在本地时区构造上月最后一天 00:00,然后 `.toISOString()` 转为 UTC。生产 Tencent Cloud 是 UTC+8,`2026-09-30 00:00 +08:00` = `2026-09-29T16:00Z`,`.slice(0,10) = '2026-09-29'`。月底(30 / 31 / 28 / 29)的凭证静默被排除。同期 Income Statement / Balance Sheet 的日期算术用 `new Date(year, month, 0).getDate()` 在本地时区直接取出 `lastDay` 数值再字符串拼接,**不**经过 `.toISOString()`,所以它们正确。

**用户 task 描述的根因(`WHERE period = ?`)是错的**:`getTrialBalance` 已经使用 `voucher_date` 范围过滤(不依赖 `accounting_vouchers.period` 列),所以 `period = NULL` 对 trial balance 无害。但 symptom(空白)是真实的,且用户要求的 canonical period semantics 修复方向正确,与本任务实际修复完全一致。

**Fix**

1. **Canonical period helper**(`server/modules/extended.js`):
   - 新增 `export function resolvePeriodRange(period)` —— 单一 canonical period 解析器。`startDate = resolved + '-01'`,`lastDay = new Date(year, month, 0).getDate()`(本地时区),`endDate = resolved + '-' + String(lastDay).padStart(2, '0')`。**不**经过 `.toISOString()`,无 UTC 偏移。
   - 重构 `calculateIncomeForPeriod` 调用 `resolvePeriodRange(period)`(Income Statement / Financial Summary 行为完全不变,源代码级 diff `~10 行`)。
2. **`getTrialBalance` 从 `app.js` 移至 `extended.js`**(`server/modules/extended.js`):
   - 删除 `WHERE active = 1 AND parent_id IS NOT NULL` —— 现在是 `WHERE active = 1`,与 Income Statement / Balance Sheet 一致。
   - 使用 `resolvePeriodRange(period)` 替代旧 `new Date(y, m, 0).toISOString().slice(0, 10)`(消除 off-by-one)。
   - 保留 `voucher_date >= startDate AND voucher_date <= endDate` 范围过滤(`period = NULL` 自动兼容)。
   - 保留 `v.status = 'POSTED'` 过滤。
   - 保留 `REPORT_VIEW` gate(`f6a2521`)。
   - 保留 response 形态 `{ trialBalance, period: { startDate, endDate } }` 与 UI 契约一致。
   - 保留每个 subject 的 `{ openingBalance, periodDebit, periodCredit, closingBalance }` 形态,`ASSET/EXPENSE = 期初+借方-贷方`,其他 `= 期初+贷方-借方`。
3. **Wire route**(`server/app.js`):
   - `import { …, getTrialBalance }` from `./modules/extended.js`(第 16 行 import list)。
   - 删除本地 `getTrialBalance` 函数(`1817-1879`)。
   - 路由注册 `if (pathname === '/api/reports/trial-balance' && req.method === 'GET') return getTrialBalance(db, res, actor, url);`(`235`)**不变**。
4. **Forward-consistency `period` write**(`server/app.js`):
   - `createAccountingVoucher`:INSERT 加 `period` 列(`id, voucher_no, source_type, source_id, voucher_date, remark, creator_id, created_at, status, period`),值 `effectiveVoucherDate.slice(0, 7)`。`effectiveVoucherDate = voucherDate || now.slice(0, 10)`。
   - `updateAccountingVoucher`:UPDATE 加 `period = ?`(`newVoucherDate.slice(0, 7)`)。
   - **不**作为修复的唯一手段:Trial Balance 仍然能正确报告历史 `period = NULL` 的凭证(因为仍按 `voucher_date` 范围过滤)。仅作为未来凭证的内部数据一致性。
5. **未变更**(严格 scope 保护):
   - Income Statement / Balance Sheet / Financial Summary 公式与语义;
   - voucher amount unit logic(`d9079f0` fix);
   - manual voucher UI + VoucherModal + VoucherDetail(`314a11d` fix);
   - VOUCHER_SUBMIT / VOUCHER_APPROVE / voucher state machine / period closing;
   - schema(`period` 列自 `db.js:140` 已存在,无新增);
   - seed data(无 parent_id 修改);
   - `legacyGetTrialBalance`(`extended.js:384`,unused by routes)保留不动;
   - `accounting.jsx` Trial Balance UI(无需改);
   - styles.css / Nginx / systemd / backup 配置。
