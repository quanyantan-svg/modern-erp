### 1.2 引擎实现要点

1. **状态机**：版本 `DRAFT→PUBLISHED→RETIRED`（已发布不可回草稿）；实例
   `RUNNING⇄SUSPENDED→COMPLETED/TERMINATED/CANCELLED`（终态不可再迁移）；节点 `PENDING→ACTIVE→COMPLETED/SKIPPED/CANCELLED`；
   任务 `PENDING→COMPLETED/CANCELLED/TRANSFERRED`。
2. **幂等**：启动键 = `document_type:document_id:version_id`，冲突**返回既有实例**（`replayed:true`），不是 409。
3. **任务完成**：事务内「重读实例状态 → 重读任务状态 + 乐观锁 → SOD 判定 → 任务与节点迁移 →
   执行节点动作（同一事务）→ 计算后继并物化 → 审计与事件」；动作失败整体回滚，任务保持 `PENDING`，副作用为零。
4. **条件求值**：八个运算符白名单 + 字段路径白名单；**禁止原型链**（`__proto__` / `constructor` / `prototype`），
   变量缺失一律 false。**不执行任何脚本**。
5. **动作契约**：注册式 handler（`FORM_WRITE` / `PUSH` / `CALLBACK` / `NOTIFY`），在业务事务内执行；
   未注册或抛错 → `PLATFORM_WORKFLOW_ACTION_FAILED`，事务整体回滚。
6. **路由前缀** `/api/platform/workflow-*`，共 16 条；**未占用** `/api/approvals/**`（6 族 canonical）
   与 `/api/workflows/**`（退役中的旧 CRUD）。

### 1.3 实现期发现并修正的四项真实缺陷

| # | 缺陷 | 处置 |
|---|---|---|
| 1 | **任何持有 `WORKFLOW_TASK_ACT` 的人都能完成别人的任务** | 新增 403 `PLATFORM_WORKFLOW_TASK_NOT_ASSIGNED`：只有被指派的参与人可以处理任务 |
| 2 | **节点实例被重复插入**（启动时全量物化 + 进入节点时再插入）→ UNIQUE 冲突 | `materializeNode` 改为**激活**既有节点实例（仅重复进入的节点才新建） |

### 1.4 实现期发现并收敛的两项合同表述

1. **`INITIATOR_MANAGER` 参与人类型不可用** —— 本仓库 `users` 表没有部门归属，
   `departments.manager` 是自由文本且从未被查询使用 → 没有权威的上级来源，不得凭空发明。
   白名单收窄为 `ROLE` / `USER` / `INITIATOR` / `FIELD_USER`。
2. **`PLATFORM_WORKFLOW_TASK_CONFLICT` 在串行化事务下不可达** —— 写事务被闸门串行化
   （SQLite `BEGIN IMMEDIATE`；MySQL 全局闸门行），并发方的真实可达结果是「任务已被处理」。
   该乐观锁是**纵深防御**，测试按其真实机制证明（过期 row_version 影响 0 行），不制造假竞态。

## 5. Attachment 子系统（PL-10，Design §32.6）

**授权来源**：业务所有者 2026-11-14 裁定「按序把四个子系统全部建完」。

- **模块** `server/modules/platform-attachments.js` —— 附件能力的唯一 owner。
- **内容不入库**：数据库只存元数据与内容寻址的存储键；文件落附件目录。
  同一内容可挂多个单据而只存一份文件。
- **上传**：`multipart/form-data`（新增 `readMultipart`，独立上限默认 10 MB）+ base64 JSON 两条路径；
  `readJson` 行为一字未改。
- **下载**走鉴权后的 API，附件目录不在静态服务范围内；固定 `Content-Disposition` 下载，不内联执行。
- **类型安全**：content type 与扩展名**双重**白名单；文件名净化；落盘键由服务端按内容摘要生成。
- **权限**：`ATTACHMENTS_UPLOAD` / `ATTACHMENTS_DELETE` 为平台级；**读取权限继承归属对象**
  （`ATTACHMENTS_VIEW` 是平台级查看权）。这是本单元的**设计修正** —— 若沿用"下载必须有
  `ATTACHMENTS_VIEW`"，新权限码只在 ADMIN 手上，附件能力对普通用户等于不可用。
- **挂载点** 7 个，按各自的**既有查看权限**判定。
- **派生计数**：`accounting_vouchers.attachment_count`（既有孤儿列）成为派生值。
- **测试** `server/platform-attachments.test.js`（13 例，已登记 FAST/FULL）。

### 实现期踩到的三个坑

1. `Content-Disposition` 里的**中文文件名**会让 Node 抛 `ERR_INVALID_CHAR`（HTTP 头只允许 latin1），
   表现为 500。改为 ASCII 回退名 + RFC 5987 的 `filename*=UTF-8''` 百分号编码。
2. 类型白名单若在 `readMultipart` 与附件模块里各判一次，拒绝码会来自两个地方 —— 判定必须唯一。
3. 派生计数的测试若断言"初始为 0"，会被前面用例的上传污染 —— 改为相对断言（+1 / 回到原值）。
