# 2026-08-31 日志

## Voucher Approval

**Goal**
为会计凭证实现完整的审核工作流：ENTERED → SUBMITTED → POSTED / REJECTED，包含 creator/approver 角色分离和状态保护。

**Key Decisions**
- 复用 `status` 字段并扩展其取值：新增 `ENTERED`、`SUBMITTED`、`REJECTED`，保留 `POSTED`；
- 使用 SQLite 表重建迁移（CHECK 约束无法 ALTER），幂等设计，已有数据默认填充为 POSTED；
- 报表（试算平衡表、财务汇总）仅计入 POSTED 状态凭证；
- `VOUCHER_SUBMIT` 和 `VOUCHER_APPROVE` 为独立权限，分属录入员和审核员角色。

**Modified Areas**
- `server/app.js`：新增 5 个凭证工作流 handler + 2 个路由（PATCH /api/accounting-vouchers/:id, DELETE /api/accounting-vouchers/:id）；
- `server/db.js`：新增 `migrateVoucherWorkflow()` 迁移 + 2 个权限 `VOUCHER_SUBMIT`、`VOUCHER_APPROVE`；
- `server/voucher.test.js`（新增）：683 行测试，覆盖单用户、多用户、自审拒绝、权限拒绝、驳回修正、审计验证、状态保护、非法转换等场景；
- `docs/02-feature-matrix.md`：凭证审核标记为完整。

**Migration**
- `migrateVoucherWorkflow()` 通过检测 CHECK 约束判断是否需要重建表；
- 已有数据库中的凭证（无 status 字段）自动填充为 `POSTED`，不影响历史数据；
- 全新数据库迁移自动执行，幂等。

**Tests**
- `pnpm test`：55 tests / 19 suites，全部通过（0 failures）；
- 新增 `voucher.test.js`：8 个 describe blocks，覆盖正常流程、异常转换、权限、审计和报表过滤。
