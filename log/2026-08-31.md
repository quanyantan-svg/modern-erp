## Supplier Schema Migration (v0.9.1 hotfix)

**Goal**
修复生产环境 v0.9.0 烟雾测试发现：`createSupplier` 在干净 SQLite 数据库上抛出 `table suppliers has no column named email`。严格限定为供应商 schema 漂移,不扩展供应商业务能力。

**Root Cause**
- `server/db.js` 中 `CREATE TABLE IF NOT EXISTS suppliers` 未声明 `email` 列;
- `server/app.js:630` `createSupplier` 在 INSERT 中包含 `email`;
- `server/app.js:642` `updateSupplier` 在 UPDATE 中包含 `email`;
- `supplierInput()`(`app.js:648`)返回 `email` 字段;
- 但 schema 本身缺少该列,生产环境 `NODE_ENV=production` + `ERP_SEED_DEMO=false` 下 DB 无 email 列、首次调用即报 `no such column: email`;
- 无 `ALTER TABLE suppliers` 兼容迁移;seed `insertSupplier` 同样不写 email(因此 demo 数据从不暴露此 bug)。

**Schema Differences**
- `suppliers` 缺失列:`email TEXT NOT NULL DEFAULT ''`(对齐 `contact / phone / address` 的模式);
- 所有其它列(`id / code / name / contact / phone / address / active / created_at / updated_at`)与 `listSuppliers` / `createSupplier` / `updateSupplier` / `supplierInput` / 其它只读 (`app.js:512,991,2428,2660`) 完全一致;
- 列表端点不返回 email,新增列仅用于写入路径;
- `customers` 等无关模块未改动。

**Migration**
- 在 `server/db.js` 的 `CREATE TABLE IF NOT EXISTS suppliers` 中加入 `email TEXT NOT NULL DEFAULT ''`(覆盖新建数据库);
- 在已有 `addColumn` 兼容迁移块中追加:
  ```
  addColumn("ALTER TABLE suppliers ADD COLUMN email TEXT NOT NULL DEFAULT ''");
  ```
  `addColumn` 使用 `try { db.exec(sql); } catch (e) {}` 模式,SQLite `ALTER TABLE ADD COLUMN` 在列已存在时报错被静默吞掉,幂等;
- `NOT NULL DEFAULT ''` 保证存量供应商行的 email 列被填充为 `''`,不破坏历史数据;
- seed `insertSupplier` 保持不变:依赖列默认值,无需修改。

**Regression Tests** (`server/supplier-schema.test.js`,9 tests / 3 suites)
- A. 干净 DB:CREATE TABLE 包含所有 supplier API 读写列;INSERT/UPDATE 含 email 列不抛错;HTTP POST `/api/suppliers` 含 email 成功(201);
- B. 旧 schema DB:模拟 `CREATE TABLE suppliers` 缺 email 的历史 DB,启动 `createDatabase()` 后:
  - 列被 ALTER TABLE 添加;
  - 旧供应商行字段完整保留(`code / name / contact / phone / address / active` 不变);
  - 新 supplier 含 email 创建成功(201),列表同时包含新旧 supplier;
  - PATCH `/api/suppliers/:id` 更新 email 成功(200);
  - 不传 email 也可创建(email 默认 `''`);
- C. 迁移幂等:在干净 DB 和旧 schema DB 上各运行 3 次 `createDatabase()`,均无报错;列仍存在;
- D. 现有数据保留:旧 schema DB 内的 `SOLD001 / 历史供应商` 完整保留,email 填充为 `''`。

**Modified Areas**
- `server/db.js`:`CREATE TABLE suppliers` 增加 `email`;`addColumn` 块增加 `ALTER TABLE suppliers ADD COLUMN email`;
- `server/supplier-schema.test.js`(新建,~280 行):9 tests 覆盖 A / B / C / D;
- `docs/00-project-status.md`:追加 "Supplier Schema Migration" 完成模块;基线 186/60 → 195/63;

## Balance Sheet

**Goal**
实现资产负债表：as-of / 期间末累计；ASSET / LIABILITY / EQUITY 三段；「未结转损益」虚拟权益行；equationValid 整数严格比较。

**Key Decisions**
- 期间语义：as-of,`asOfDate = LAST_DAY(period)`;所有余额按 `voucher_date <= asOfDate` 累计
- 不显示期初余额列(标准资产负债表形态)
- 期末余额 = 沿用试算平衡表 / 会计余额的方向规则:ASSET `debit-credit`,LIABILITY / EQUITY `credit-debit`
- 当前 schema 无自动损益结转机制,资产负债表通过**未结转损益**虚拟权益行补偿

- 扩展恒等式:`Assets = Liabilities + Posted Equity + Unclosed Profit`
- `equationValid` 为正式响应字段,使用整数 cents 严格比较 `difference === 0`,无浮点容差
- EQUITY 测试 fixture 自行添加(`subject-4001 / 4001 / 实收资本 / EQUITY / CREDIT`),不修改全局 production demo seed
- OPEN / CLOSED 期间均可查询,只读操作不调用期间写保护
