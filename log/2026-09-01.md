## Phase D — Hotfix: Project Manager Selector Population (v0.9.4 → v0.9.5 candidate)

**Goal**

修复 Phase D production browser verification 阶段由用户在腾讯云生产环境确认的最后一个 project-creation UX blocker：`项目立项 → 新建项目 → 项目经理` 下拉框渲染但没有可选用户。严格限定 scope:只动 `ProjectModal` 的用户数据加载 + 新增最小化只读 lookup endpoint,不动其他 modal、其他 module、其他 schema、其他 permission。

**Root Cause**

`src/pages/projects-workflow.jsx:104` 渲染下拉项时使用了 `{u.name}`,但 `GET /api/users` (`server/app.js:567-575`) 返回的是 `{ id, username, displayName, active, ... }` —— 字段是 `displayName`,**没有 `name`**。`u.name === undefined`,React 渲染空白文本,占位符 `<option value="">选择经理</option>` 成为唯一可见内容,从用户视角看到的是"下拉框没有用户"。

**潜在次要风险(同一 defect class)**

`GET /api/users` 由 `allow(actor, 'USERS_MANAGE')` 守卫。admin role(`role-admin: all`)具备该权限,因此当前在 production 单 admin 环境下不会 403;但 seed 的 `role-sales / role-reviewer / role-accounting / role-warehouse` 全部**不含** `PROJECT_MANAGE`(它们都不该新建项目),所以任何具备 `PROJECT_MANAGE` 但**不具备** `USERS_MANAGE` 的未来角色一旦出现,modal 会变成静默 403 + 空数组,本任务的设计顺便消除了这一隐患。

**Fix**

1. **后端**: 新增最小只读 handler `listProjectManagerCandidates` (`server/app.js:578-587`),挂载在 `GET /api/users/lookup`。
   - 守卫: `allow(actor, 'PROJECT_MANAGE')` —— 与 `createProject` / `updateProject` 的 contract 完全对齐;**不**回退到 `USERS_MANAGE`。
   - 返回字段: `{ id, username, displayName, active }` —— 仅 4 个字段,**不**含 password_hash / salt / role / createdAt / token。
   - 过滤: `WHERE u.active = 1`(只活跃用户可作为项目经候选人)。
   - 排序: `display_name, username`(stable UX)。
   - 现有 `listUsers` (`server/app.js:568`) **完全未动** —— 仍然是 `USERS_MANAGE` gate,administration 授权**没有**被弱化。
2. **前端** (`src/pages/projects-workflow.jsx:74-77, 104`):
   - `api('/api/users')` → `api('/api/users/lookup')`;
   - `{u.name}` → `{u.displayName || u.username}`(主:显示名;退路:登录账号);
   - 两次 `fetch` 都加 `.catch`: customers `.catch(() => {})`(静默 —— 这是已有的 fallback 行为),users `.catch((e) => notify(e.message, 'error'))` —— 4xx/5xx 走 `notify`,不再 unhandled rejection。
3. **未变更**(严格 scope 保护):
   - `ProjectModal` 的 function signature `{ user, notify, value, onClose, onSaved }`(`3d1a973` 修复 contract 完整保留);
   - `useState` initializer `manager_id: user?.id || ''`(当前用户作为默认经理) + `...value`(编辑模式覆盖,保留既有经理);
   - `Projects` parent 调用 `<ProjectModal user={user} notify={notify} ... />`(`3d1a973` 修复);
   - `<Badge>` 引用 + import(`b8556f4` 修复);
   - `manufacturing.jsx` 中的 `PRODUCTION_ORDERS_*` canonical permission + `allowAny` cancel contract(`3d1a973` + `0c15bd9` 修复);
   - `createProject` / `updateProject` / `getProjectDetail` 的 backend SQL(`server/modules/business.js:153-208` 完全未动),仅前端切换了读取候选用户的数据源;
   - 其他 modal(`TaskModal` / `TimesheetModal` / `WorkflowModal`)的 `/api/users` 调用 —— **不在本次 scope**,任务明确"不要修改无关 ERP 模块";它们仍可能因 `USERS_MANAGE` 缺失而静默失败,但本任务不处理;
   - accounting / voucher / period closing / supplier migration / master data / Nginx / systemd / backup / styles.css 完全未动。

**Schema Changes = NONE**

- `projects` / `users` schema 未改;FK `manager_id REFERENCES users(id)` 已被 enforce(`PRAGMA foreign_keys = ON` 在 `db.js:114`),非法 `manager_id` 在 INSERT 时被 SQLite 拒绝(测试已覆盖)。

## Phase E — Hotfix: Manual Voucher Workflow + role-accounting VOUCHER_SUBMIT (v0.9.4 → v0.9.5 candidate)

**Goal**

修复 Phase E production browser verification 阶段由用户在腾讯云生产环境确认的最后一个 blocker:`role-accounting / 财务专员` 登录后,`会计凭证 → 凭证列表` 没有任何 `＋ 新建凭证` 入口。同时补齐最小化 manual voucher workflow UI(创建 / 编辑 / 提交 / 审核 / 驳回)、MANUAL source label 错误映射、role-accounting 缺失 `VOUCHER_SUBMIT`。严格 scope:不动 schema、不改 reporting、不改 permission model、不动其他 module。

**Root Cause**

审计发现四个独立问题叠加:

1. **`src/pages/accounting.jsx` 的 voucher tab** 没有 `+ 新建凭证` 按钮,只有 Toolbar + 表格 + `查看` 按钮。backend 早就具备 `createAccountingVoucher` (`server/app.js:1462-1500`,`ACCOUNTING_VIEW` gate,创建为 `MANUAL`/`ENTERED`),但前端从未提供入口,导致单 admin 之外的角色无法发起凭证。
2. **`voucher.source_type` label 错误映射**:`vouchers` 列表(line 242)+ `VoucherDetail`(line 507)都是三元 `SALES_ORDER → '销售订单' / PURCHASE_ORDER → '采购订单' / else → '库存调拨'`。`MANUAL` 走 else 分支,**手工凭证被错误显示成 `库存调拨`**。
3. **`role-accounting` 缺少 `VOUCHER_SUBMIT`**:`db.js:1129` 的 role-accounting 数组仅含 `ACCOUNTING_VIEW + REPORT_VIEW + 业务查看权限`,无 `VOUCHER_SUBMIT`。即便补齐 UI,`ENTERED → SUBMITTED` transition 也会被 backend 拒绝(403)。
4. **`VoucherDetail` 无 submit / approve / reject UI**:仅 readonly 详情,不能驱动现有 backend state machine。

**Fix**

1. **Backend permission reconciliation**(`server/db.js:1129`):
   - `role-accounting` 数组插入 `'VOUCHER_SUBMIT'`(位置 3,与 `ACCOUNTING_VIEW` 相邻)。
   - 不加入 `VOUCHER_APPROVE`(separation of duties:财务专员只制单 + 提交,审核由 admin / 独立审核角色负责)。
   - 不引入新的 reconciliation mechanism —— 现有 `seedSchema` 的 `INSERT OR IGNORE INTO role_permissions(role_id, permission_code)` 在 `role_permissions` 表的主键 `(role_id, permission_code)` 上已是幂等的:missing 行被插入,existing 行被跳过。production 启动一次自动 reconcile,无需手工 SQL,不需要新的 migration,也不依赖 `ERP_SEED_DEMO`。
2. **Frontend UI**(`src/pages/accounting.jsx`):
   - 模块顶部新增两个 label map:`VOUCHER_SOURCE_LABELS`(`MANUAL → 手工凭证`,`SALES_ORDER → 销售订单`,`PURCHASE_ORDER → 采购订单`,`INVENTORY_TRANSFER → 库存调拨`,未知 source 返回 raw 字符串) + `voucherSourceLabel()` helper。`VOUCHER_STATUS_LABELS` + `VOUCHER_STATUS_BADGE`(4 状态映射到既有 `.status.*` CSS,POSTED 复用 `.status.completed` 因为无 `.status.posted` —— CSS 严格不动)。
   - `Accounting` parent:新增 `editing` state + `loadVouchers()` 函数 + `canCreateVoucher = can(user, 'ACCOUNTING_VIEW')` 守卫;Toolbar 新 action: `＋ 新建凭证`;voucher 列表加 `状态` 列(Badge)+ `voucherSourceLabel(v.source_type)` 替换原三元。
   - `VoucherModal`(新建):支持创建 + 编辑(REJECTED → ENTERED,backend `updateAccountingVoucher` 行为);前端 UX validation(`至少需要两条分录` / `科目不能为空` / `金额必须大于 0` / `借贷不平衡`);保存时 POST `/api/accounting-vouchers` 或 PATCH `/api/accounting-vouchers/:id`;amount 用 `amountCents` 整数 cents 字段(对齐 backend contract,**不在前端做 yuan→cents 转换**);实时显示借/贷合计 + `借贷平衡 / 不平衡` 状态;backend validation 仍然是最终安全边界。
   - `VoucherDetail`(改写):顶部加 `<Badge>` 状态 + 修正后的 source label;`已驳回` 时显示 `rejection_reason`;actions 按 state × permissions gating:
     - ENTERED + ACCOUNTING_VIEW: 编辑 / 删除
     - ENTERED + VOUCHER_SUBMIT: 提交
     - REJECTED + VOUCHER_SUBMIT + MANUAL: 重新提交(backend `submitAccountingVoucher` 接受 ENTERED + REJECTED)
     - SUBMITTED + VOUCHER_APPROVE + creator !== 当前用户: 审核通过 / 驳回(驳回要求输入 `rejectionReason`,trim 非空)
     - REJECTED + ACCOUNTING_VIEW: 编辑(回到 ENTERED,backend 自动 reset)
     - POSTED: 只读,显示 `已过账凭证为只读`。
3. **未变更**:
