## M1C-G07-PARITY-R4-R2 严格性补丁：CAST 字符集不得无条件丢弃

- baseline：`master` @ `53ebf0cf1d1fb58b64b2c9083c34b530ecc2e649`（R4-R1 提交，亦为第二轮独立
  审查的审查 SHA）；任务开始时工作树 clean，HEAD 与审查 SHA 一致。
- 授权：Owner 授权对第二轮独立审查的新发现做**最小定向修复**（仅比较器、负向测试与必要的
  候审证据），并授权 Fast-forward 推送至原 R4 审查分支
  `review/m1c-g07-parity-r4-20261106`。
- 审查结论：确认 R4-R1 的两项阻塞（字面量类别、CAST 类型参数）**均已关闭**。新增发现一项：
  `parseCast()` 读取**任意** CHARSET 后直接丢弃，可能将 `utf8mb4` 与 `latin1` 的不同 CAST
  表达式误判为相同。
- 复现：修复前 `CAST(x AS CHAR CHARSET utf8mb4)` 与 `CAST(x AS CHAR CHARSET latin1)` 的规范形
  均为 `C:(cast (id x) char)`，两者**相等**——即误判。
- changes：
  - `server/test-utils/m1-core-schema-parity.js` 的 `parseCast()`：读取字符集子句的**名称**，
    仅 `utf8mb4` 视为冗余（与无 charset 子句等价），其余字符集名称（`latin1`、`ascii` 等）
    保存在 AST 中；`renderExpressionAst()` 的 `cast` 分支把字符集渲染进规范形。
  - `server/test-utils/m1-core-schema-parity.js` 的解析器说明注释：补记字符集规则。
  - `server/m1-core-g07-infrastructure.test.js` 新增 2 个 R4-R2 负向测试：字符集不得被合并
    （含已批准等价的正向断言），以及生成列 digest 的错误字符集必须触发
    `GENERATED_COLUMN_EXPRESSION`（latin1 与 ascii 均触发；已批准的 utf8mb4 仍判为相等）。
  - `docs/acceptance/m1-core-g07-parity-r4-review-20261106.md` 新增 §9 记录第二轮审查结论与
    R4-R2 修复证据，§3.3 补记 CAST 字符集行，§7 结论 token 更新；
    `docs/acceptance/README.md` 同步登记行。
- 设计取舍：采用**保留字符集名称进 AST**而非安全拒绝。安全拒绝会使含该字符集的**整个**
  CHECK 子句退化为 token 流比较，而 MySQL 目录会给布尔操作数加括号，结构等价的对将因括号
  差异被误判为不等；保留名称可同时满足「不误判相等」与「不引入误判不等」。已批准的等价
  `CAST(x AS CHAR)` ≡ `CAST(x AS CHAR CHARSET utf8mb4)`（MySQL 目录冗余地标出连接字符集）
  原样保留；词法层既有的 `normalizeGeneratedCastCharset` 归一未改动，与 AST 层规则互为冗余。
- 边界：**未重写 AST**，只改 `parseCast()` 的字符集处理与 `cast` 分支渲染；未引入任何新的
  无依据等价规则（非 `utf8mb4` 字符集只会让比较更严格）。
- 不变项：生产 Handler、DDL、Migration、Fixture、已批准 digest、CR-01～CR-09、Supplemental Oracle、
