## Wave 8 Stage D — one-shot P0/P1 remediation & acceptance evidence closure

### Baseline

  pre-existing user file, SQLite/WAL/SHM artifact and untracked file was preserved.

### Scope and changes

- P0-1: `settleConsignmentLineCommand` refuses a non-positive cumulative event amount with
  `CONSIGNMENT_SETTLEMENT_AMOUNT_NOT_POSITIVE` before any mutation; Finance recognition and the settlement
  voucher became unconditional. The Finance settlement source now carries the §35.18.7 immutable
  `CS:<lineId>:<sha256(key)>` event identity — previously it carried the shared consignment `document_no`,
  so every settlement after the first on a document collided on the unique
  `account_receivables.voucher_no` and **no consignment document could ever be settled twice**.
- P0-2: `assertSoBackedConsignmentBasis()` locks and reads the approved SO line, requires 1:1 Sales UOM,
  verifies the stored discount snapshot still agrees with the source amount, derives the exact net unit
  price and refuses a submitted price that differs, and enforces remaining approved source capacity.
  Unrepresentable bases fail closed as `CONSIGNMENT_COMMERCIAL_BASIS_UNREPRESENTABLE` with a reason.
- C1: both gate entry points now perform unlocked discovery, lock the Finance PREPAYMENT parents by id ASC,
  and only then take Gate requirement/result locks, matching §35.18.6. Caller audit recorded in `solution.md`.
- Consignment entitlement is aggregated per `(lineId, to_position_key)` bucket and deducted once;
  `mutationIds` keeps every handoff individually inspectable.
- Handoff verifies the declared source warehouse and bin before V21 runs.
- Valuation `movementType` now carries the canonical source position so one document's partitions no longer
  collide on `idx_valuation_source_identity`. V21 schema/index/writers are unchanged.
- `createSalesDelivery` no longer demands physical stock for service-classified lines; service Delivery was
  otherwise impossible to create at all.
- Three-layer report now validates evidence and reports an explicit discrepancy instead of returning
  `RESOLVED` whenever a movement group id exists.
- RBAC read is `SALES_MANAGE OR SALES_VIEW` plus the narrow permission. `SALES_VIEW` is new in this wave with
  approved basis; the total permission count is unchanged.
- Wave 8 MySQL migration gained a read-only `information_schema` physical-contract assertion that fails
  closed on drift and never repairs. `lot_code_key`'s binary-collation gap is exported as
  `WAVE8_KNOWN_MYSQL_PARITY_GAPS` (`EXTERNAL_CONTRACT_REQUIRED`).
- R-SAL-21 was rewritten to prove both orderings (settlement wins / return wins) with a per-line footprint
  across commercial remaining, partition remaining, V21 physical balance, transactions, tracking, valuation,
  COGS, AR, audit and idempotency.
