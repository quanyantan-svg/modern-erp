  `waitForTransactionRetry()` `db.js:1870-1872`, `mysql-worker.js:26-31/:95-98`.

### Verified corrections

- **READ COMMITTED semantics.** Removed the unconditional claim that an ordinary
  SELECT under READ COMMITTED "always sees a recent committed image" / "is not
  staleness" (§37.17.2). Corrected position (§37.23): each consistent read uses a fresh
  statement-level snapshot; an ordinary SELECT does not lock the queried business rows;
  another transaction may commit a relevant change afterwards; an unlocked discovery
  read is candidate input only and never mutation authority; final validation must use
  the authoritative rows held under the approved L1..L8 order; candidate identity and
  fingerprint are revalidated immediately before mutation. No unconditional guarantee
  is made about freshness at commit time. The approved §37.17.3 final-lock design —
  consume the locked `{delivery, order}` pair from `lockAndConsumeSalesDeliveryCapacity`
  (sales-delivery-source.js:79) and build the Service fingerprint from the rows locked
  at service-fulfillment.js:163/:164 rather than the unlocked snapshot at :160 — is
  preserved unchanged. MySQL isolation configuration unchanged.
- **Retry budget.** `mysqlTransactionRetryLimit()` reads `ERP_DB_TX_RETRY_MAX`, default
  3, accepted only as a safe integer in [0,10] and otherwise falling back to 3, so the
  inner limit is configurable, not fixed. `transaction()` runs
  `for (let attempt = 0; ; attempt += 1)`, giving inner attempts = limit + 1: 4 by
  default, 11 at the configured maximum. With outer rediscovery attempts capped at 3,

  via `Atomics.wait` on the main thread, so an in-flight synchronous operation cannot be
  interrupted and the inner loop contains no elapsed check. The elapsed deadline is
  therefore **retry admission control**, not a hard bound; the only enforceable bound is
  the attempt count. Rollback-before-retry, named idempotency lock release on commit and
  throw paths, fresh discovery on stale-plan retry, non-retry of business 409, explicit
  exhaustion as 503, and no duplicate monetary or audit effect are all preserved.
