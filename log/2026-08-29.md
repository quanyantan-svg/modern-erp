## 修复：API 500 错误全面修复 | 2026-08-29

**问题**：多个 API 端点返回 500 内部服务器错误，包括供应商资料、仓库资料、库存管理、退货管理、入库单、发货单、收款记录、库存台账。

**根本原因**：多处代码与数据库 Schema 不匹配，以及一个关键语法错误：

1. **savePurchaseOrderItems 缺少闭合 }**：server/app.js 第 809 行，函数体未关闭，导致后续所有函数被错误嵌套，运行时 listWarehouses is not defined

2. **表名不一致**：
   - sales_returns → DB 中为 eturn_orders
   - sales_return_items → eturn_order_items
   - ccounts_receivable → ccount_receivables
   - ccounts_payable → ccount_payables
   - purchase_returns 表不存在

3. **缺失列导致 SQL 错误**：
   - eturn_orders 缺少 confirmed_by、confirmed_at（ALTER TABLE 动态添加）
   - inventory_checks 缺少 product_id、system_quantity、ctual_quantity、difference、eason、eviewer_id、eviewed_at、emark（ALTER TABLE 动态添加）
   - inventory_transactions 没有 creator_id（移除 creator JOIN）
   - payment_collections 没有 payment_collection_items 子表（移除子查询）

4. **SQL 语句错误**：
   - listPurchaseReceipts：WHERE  ORDER BY 中间少了 + where +
   - 多个函数 JOIN 了不存在的列（confirmed_by vs handler_id）

5. **INVENTORY_CHECK_STATUS 常量未定义**

**修复方案**：
- 在 savePurchaseOrderItems 函数后添加缺失的 }
- 替换所有错误的表名（sales_returns → eturn_orders 等）
- 在 db.js 的 createDatabase 中添加 ALTER TABLE 动态补充缺失列
- 修复 listPurchaseReceipts 的 SQL 查询模板字符串
- 修正 purchase_receipts 使用 handler_id（非 confirmed_by），purchase_returns 使用 confirmed_by
- 添加 INVENTORY_CHECK_STATUS 常量
- 移除 inventory_transactions 和 payment_collections 中不存在列的引用

**修复的文件**：
- server/app.js：修复语法错误、表名、列引用、常量
- server/db.js：添加缺失列的 ALTER TABLE 动态补充

**最终状态**：所有 17 个 API 端点返回 200 OK（或 403 权限错误），BOM 和生产工单因管理员角色未配置权限而返回 403。
