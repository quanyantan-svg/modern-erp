## Finance Operations Domain — RACE-15 Ordering Closure

- Single outstanding contradiction against the preflight review: the previous RACE-15 attempt inferred serialization ordering from final-row existence (`if closed_through_date == dateLate then collection == 0`). That rule is invalid because the legal transaction-first outcome legitimately leaves both `closed_through_date=dateLate` AND `collection_date=dateLate` in the final state — they only serialize because the collection committed before the close.

- Fixed by replacing the inference-by-final-state with deterministic explicit worker coordination:
  - Worker now exposes a held-session state machine. New actions: `acquire-anchor` (BEGIN + SELECT FOR UPDATE on the close anchor and stay in that connection's transaction), `extend-held-collection` / `extend-held-close` (continue running inside the held transaction without re-BEGIN), `commit-held` (COMMIT + clear state), `rollback-held` (ROLLBACK + clear state).
  - The orchestrator drives A → commits → dispatches B, eliminating sleep-based timing. Each worker holds the anchor lock only on its own MySQL connection; serialization is owned by InnoDB row-level locking on `finance_business_close_state WHERE close_type=?`.

- RACE-15 split into two required subcases, kept under one Race ID:
  - RACE-15A — transaction obtains anchor first. Worker A acquires → extends with a dated collection write INSIDE the held transaction → commits → worker B dispatches the close. Both succeed. Final assertions: `collection_count = 1`, `closed_through_date = dateLate`, `finance_business_closures` count = 1, behind-close writes = 0.
  - RACE-15B — close obtains anchor first. Worker A acquires → extends with a close write INSIDE the held transaction → commits → worker B dispatches a dated `collection-allocate`. assertFinanceBusinessDateOpen rejects because `dateLate <= closed_through_date`. Final assertions: zero collection rows, zero treasury movements from the rejected tx, `closed_through_date = dateLate`, exactly one `finance_business_closures` history row. Rejection reason includes the canonical `CLOSED_DATE` / `ALREADY_CLOSED` code or the localized "已结账" message.

- Forbidden outcome made explicit (now impossible, not inferable): close commits `closed_through_date = dateLate` AND a transaction dated `<= dateLate` commits afterwards. RACE-15B explicitly fails if `closureHistory > 0 && collectionCount > 0`.

- Stable anchor evidence: both subcases use `close_type = 'AR'` against the same seeded `finance_business_close_state WHERE close_type = ?` row. The lock acquisition precedes the work, and the lock release precedes the second worker's dispatch — the orchestrator waits for the held worker's COMMIT response before sending the second worker's request.

- RACE-10 matrix typo correction: the prior matrix row reported "≤ 1 AP recognition" for sales-invoice; that is wrong because sales-invoice → AR. The test code already asserted `account_receivables` (AR) row count `<= 1`. The matrix table and any future report now read "≤ 1 AR recognition" for RACE-10. Production semantics unchanged.
