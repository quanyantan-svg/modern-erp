- 记录生产事故（MySQL `wait_timeout=28800` 关闭长连接 → readiness 长期 503 → 必须重启 Node）；
- 冻结：连接配置与会话设置保留 / 可恢复连接错误中央分类 / 写绝不自动重试 / 只读仅一次重试 / 写失败清理 / 事务丢失 / close 语义 / 失败驱动恢复 / 不允许伪修复（不调 `wait_timeout` / 不引入 cron / 不引入 watchdog / 不引入周期性 HTTP 探活）；
- 明确 P2 不重写数据库层、不迁移 pool、不改 schema / 迁移 / API / 角色 / 审批族 / 业务合同 / SQLite 路径。

### STAGE 2 — DESIGN

- 在 `solution.md` 新增第 35 节，设计 worker 内 `openConnection()` / `ensureConnection()` / `isRecoverableConnectionError()` / `isReadOnlySql()` / `classifyExecStatement()` 五个中央函数 + 状态机 + 失败驱动恢复路径表；

- 设计 disposable MySQL 集成测试：独立控制连接对 adapter session 执行 `KILL CONNECTION`，验证重连 / 会话设置 / 事务丢失；
- 明确不引入 ping、不重写数据库层、不引入 pool。

### STAGE 3 — IMPLEMENTATION

- `server/database/mysql-worker.js`：
  - 新增 `RECOVERABLE_CONNECTION_CODES` 与 `isRecoverableConnectionError(error)`，覆盖 mysql2 / Node 传输级错误码 + 文本特征；
  - 新增 `isReadOnlySql(sql)` 与 `classifyExecStatement(sql)`；
  - 提取 `openConnection(config)`：createConnection + `error` 事件挂钩 + 按序 `SET time_zone / TRANSACTION ISOLATION LEVEL / innodb_lock_wait_timeout`；
  - 引入 `ensureConnection()`：缺连接或 socket 已销毁时按保留配置重连并应用会话设置；
  - 引入 `discardStaleConnection(reason)`：清空引用、best-effort `destroy()`、事务状态重置并发 `mysql_connection_lost`；
  - `query` 失败时仅当 read-only 且不在事务中才重试一次；其他动作一律丢弃连接、不重试；
  - `close()` 标记 `closed = true`、对健康连接尝试 `end()`、失败时放弃、不重建；
  - 通过 `mysql_reconnect_attempt` / `mysql_reconnect_success` / `mysql_reconnect_failed` / `mysql_connection_lost` / `mysql_transaction_lost` 五个事件做最小可观测；
