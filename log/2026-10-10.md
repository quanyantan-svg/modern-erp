### Frozen Core Invariants

Requirement 必须保持以下 invariant，Design / Implementation 不得破坏：

- **I1 — One Physical Stock Truth**：所有业务域最终使用同一 physical inventory truth；禁止第二库存账。
- **I2 — Location ≠ Ownership**：warehouse / location 与 owner 解耦；至少支持 enterprise-owned @ enterprise warehouse、enterprise-owned @ supplier-WIP warehouse、supplier-owned @ enterprise warehouse（VMI）、customer-owned @ enterprise warehouse（entrusted material）。
- **I3 — Business Document ≠ Inventory Mutation**：采购 / 销售 / 生产 / 委外拥有业务单据；Inventory 提供唯一 physical mutation contract。
- **I4 — On-hand ≠ Reserved ≠ Available**：on_hand / reserved / available 必须分明；Planning owns reservation intent；Inventory owns physical availability projection。
- **I5 — LOT / SERIAL Is Canonical**：LOT、SERIAL、expiry 不得由各业务域重复维护。
- **I6 — Stock Status Is First-Class**：库存状态影响 availability / issue / shipment / transfer / reservation eligibility。
- **I7 — Business Date / Period Is Authoritative**：库存动作必须服从业务日期与库存期间。
- **I8 — Quantity Truth ≠ Final Cost Truth**：Inventory owns physical quantity；Finance owns final financial costing / accounting。

### 7 Design Consistency Corrections（summary）

1. **Lock truth 去重（§27.4 + §27.15）**：移除 `inventory.is_locked` 列。Lock 唯一 truth = `inventory_locks`。`inventory` balance 只保存 physical quantity + dimensions。
2. **Planning reservation 三量（§27.13 + §27.14）**：
   - `active_reserved_total = ACTIVE STRONG + WEAK + MANUAL`
   - `hard_reserved = ACTIVE STRONG + MANUAL`
   - `soft_reserved = ACTIVE WEAK`
   - `physical_free = eligible_on_hand - active_locks`
   - `available_for_new_reservation = physical_free - active_reserved_total`
   - `available_for_unrelated_execution = physical_free - hard_reserved`
   - 不重写 Planning frozen STRONG / WEAK / MANUAL semantics。
3. **MySQL-incompatible partial unique 替换（§27.7）**：移除 `uq_tracked_post ... WHERE reversed=0`。改用：
   - canonical `idempotencyKey` plain UNIQUE（单次入口 single-effect authority）；
   - 普通 composite UNIQUE（无 `WHERE` 子句）；
   - reversal 通过显式 `reversal_of_movement_id` 关系 + 新的 reversal movement 表达。
4. **IN / OUT 物理方向强制（§27.6 + §27.7 + §27.19）**：`tracked_inventory_movements.direction` 仅保留 `IN / OUT`；业务 mutation 类型由 `movement_kind` + `movement_group_id` 表达。Direct Transfer / BIN_MOVE / OWNER_CHANGE / STATUS_CHANGE / LOT_RECLASS 一律为 paired OUT + IN，同 `movement_group_id`，同一 transaction。
5. **Canonical lock ordering（§27.17 + §27.18）**：
   - 收集本次 transaction 涉及的全部 `position_key`，deduplicate；
   - 按字典序 ascending 排序；
   - 严格按排序结果加锁；
   - 禁止 always-from-first / always-to-first（避免反向 transfer deadlock）。
   - SQLite：`BEGIN IMMEDIATE`；MySQL：`SELECT ... FOR UPDATE`。
6. **Atomic legacy cutover（§27.43.1 + §27.44）**：
   - 全部 physical inventory WRITE paths 必须收敛到 `applyInventoryMutation`；
   - `adjustInventory()` 必须替换或降级为 compatibility adapter（仅 ENTERPRISE + AVAILABLE + NULL bin + no tracking）；
   - owner-aware / status-aware / bin-aware / tracking-aware 路径禁止调用 `adjustInventory()`；
   - activation gate：SUPPLIER / CUSTOMER owner / non-default bin / non-AVAILABLE 正式 writable 之前必须证明全部 physical mutation callers 完成 convergence；
   - 旧 read 必须走 `inventory_compatibility_view`（SUM canonical positions），禁止 `SELECT one arbitrary inventory row WHERE warehouse_id=? AND product_id=?`。
7. **LOT / SERIAL lifecycle 分层（§27.12）**：
   - position 数量归零 ≠ identity 终结；
   - tracking identity lifecycle 变化仅通过 canonical tracking lifecycle rules（Domain 2 冻结）；
   - Domain 5 不重写 `inventory_lots.status` / `inventory_serials.lifecycle_state` 状态机；
   - Inventory 仅消费已发布的 tracking identity 状态作 availability / issue / shipment 校验。

### 8 / 9 增量细节

- **position_key 物理映射（§27.3）**：SQLite `TEXT NOT NULL UNIQUE` + 应用层 length / lowercase-hex validation；MySQL `CHAR(64) NOT NULL UNIQUE`（**禁止** MySQL `TEXT UNIQUE`）。
- **Step transfer 派生（§27.20）**：`inventory_step_transfer_in_transit` **只**保存 execution facts；canonical derivation：

  in_transit_qty = issued_qty - received_qty - returned_qty - cancelled_qty
