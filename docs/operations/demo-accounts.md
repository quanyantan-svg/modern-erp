# 演示与验收账号指南

本文说明如何安全地为课堂、验收或隔离演示环境配置账号。账号不是当前需求或权限定义的权威来源；角色合同以 [document.md](../../document.md) 和当前代码为准，演示步骤见 [demo-business-flow.md](./demo-business-flow.md)。

## 五个正常角色

系统正常角色固定为以下五个，不应为了演示创建第六个业务角色：

| 角色 | 演示职责 | 关键限制 |
|---|---|---|
| `ADMIN` | 系统配置、主数据、计划/制造管理、异常管理、当前模型中的手工凭证审批 | 不能审批自己创建的凭证 |
| `SALES` | 客户/供应商、CRM、销售订单、采购订单和请购单的创建与提交 | 不执行库存、会计或审批动作 |
| `REVIEWER` | 审核销售订单、采购订单、请购单和库存盘点 | 不创建普通交易，不自审 |
| `WAREHOUSE` | 收发货、退货、IQC/OQC、盘点提交、调拨、调整、报废和制造库存执行 | 不负责商业计价、结算、会计或通用审批 |
| `ACCOUNTING` | AR/AP、收付款、折让/贷项、退款、核销、手工凭证提交和报表 | 不执行库存/制造，不能审批自己创建的凭证 |

前端隐藏入口只是体验控制；后端仍对每个请求执行认证、权限和业务状态校验。

## 账号命名

隔离演示环境可以使用 `test_admin`、`test_sales`、`test_reviewer`、`test_warehouse`、`test_accounting` 等可识别名称，并分别绑定现有角色。名称只是示例，不表示生产环境会自动创建这些账号。

生产必须保持 `ERP_SEED_DEMO=false`。不要把演示账号当作长期共享生产账号。

## 安全创建流程

首个管理员仅通过显式命令创建：

    pnpm setup-admin -- --username <operator-name> --password '<provided-securely>'

其他账号应由持有用户管理权限的管理员通过系统用户管理界面或受认证 API 创建，并绑定现有角色。不得修改角色权限来迁就演示脚本。

密码要求：

- 由项目负责人通过仓库外安全渠道提供；
- 每个账号使用不同强密码；
- 不使用已知演示弱密码；
- 不写入本文、`.env`、日志、截图、测试数据或 shell 历史；
- 演示完成后停用或轮换。

本文有意不提供任何可复用密码、密码哈希、Token、API key 或生产连接信息。

## 推荐职责分离演示

1. `SALES` 创建并提交销售订单或采购订单。
2. `REVIEWER` 以不同账号审核。
3. `WAREHOUSE` 执行质量门禁与出入库。
4. `ACCOUNTING` 处理发票/账单、结算或提交手工凭证。
5. `ADMIN` 在创建人与审批人不同的前提下审批手工凭证，并演示系统管理能力。

演示环境仍必须遵守来源、期间、库存、金额、幂等和审计规则；不要为了展示效果绕过后端校验。

## 生命周期

- 演示前确认环境、数据范围和允许动作。
- 演示中避免执行生产恢复、全量重置、历史重写或未获批准的关账操作。
- 演示后撤销临时 Token，停用不再使用的账号，并保留必要审计记录。
- 若需要复现数据，使用隔离测试数据库和经过批准的 seed/fixture，不复制生产凭据或生产数据。
