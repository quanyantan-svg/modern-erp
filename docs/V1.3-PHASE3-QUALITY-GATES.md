# V1.3 Phase 3：权威 IQC / OQC 质量门禁

## 边界

IQC/OQC 是物流确认前的作业质量门禁，不是通用审批、库存单据或会计单据。它们不进入审批中心；审批中心仍仅包含销售订单、采购订单、采购申请、库存盘点和会计凭证五类。

IQC/OQC 的创建、更新、完成、取消本身均不改变库存，不生成应收/应付，也不生成凭证。库存及财务影响仍由采购入库确认和销售出库确认唯一拥有。

## 权威来源图

```text
APPROVED Purchase Order
  -> Purchase Receipt DRAFT
  -> IQC DRAFT -> COMPLETED PASS
  -> Purchase Receipt CONFIRM
  -> stock + / AP / voucher

APPROVED Sales Order
  -> Sales Delivery DRAFT
  -> OQC DRAFT -> COMPLETED PASS
  -> Sales Delivery CONFIRM
  -> stock - / AR / voucher
```

新 IQC 必须引用 `purchase_receipt_id`，每条检验明细必须引用 `purchase_receipt_item_id`。新 OQC 必须引用 `sales_delivery_id`，每条检验明细必须引用 `sales_delivery_item_id`。这些列是可空外键，以便旧版未关联记录继续可读；V1.3 API 对新写入强制要求非空且有效。旧 `receipt_id` / `delivery_id` 自由文本字段不用于质量门禁，也不会被迁移脚本伪造。

## 来源字段与快照

创建质量单时，后端从物流草稿继承并锁定：

- 来源订单、来源物流单及来源行 ID；
- 供应商或客户；
- 产品、数量、单位；
- 仓库；
- 批次（当前物流模型存在时）；
- 收货/发货业务日期上下文；
- 物流单携带的订单价格仅可在物流上下文显示，质量界面不提供价格输入。

逐行保存 `snapshot_quantity`、`snapshot_warehouse_id`、`snapshot_batch_no`，产品和来源行 ID 保存在检验明细中。质量草稿更新只允许检验日期、检验类型、抽样数量、备注等质量数据；来源单、往来单位、产品、来源数量及来源行均不可变更。选择错误来源时应取消草稿并重建。

## 状态机

IQC 与 OQC 使用同一逻辑状态机：

```text
DRAFT -> COMPLETED (PASS | FAIL)
DRAFT -> CANCELLED
```

旧版 `PENDING` 记录仅作为兼容草稿状态读取。新单写入 `DRAFT`。

- `DRAFT`：可修改质量信息、可取消，没有库存或财务副作用。
- `COMPLETED`：结果最终且普通业务流程不可修改或删除。
- `CANCELLED`：保留历史，不满足门禁。

完成时，检验数量必须大于零并等于来源物流各行数量之和；合格数与不合格数必须均非负且相加等于检验数量。PASS 要求不合格数为 0 且全部合格。FAIL 要求不合格数大于 0，并填写缺陷原因和处置方式。

IQC 失败处置：`HOLD`、`REWORK`、`REJECT_TO_SUPPLIER`。OQC 失败处置：`HOLD`、`REWORK`、`SCRAP_REVIEW`。失败只记录处置，不自动产生采购退货、销售退货或库存移动。

## 失效与复检

确认物流单时，系统重新读取当前物流单和全部明细，并把来源单 ID、来源行 ID、产品、数量、仓库和批次与最近一张权威质量单的不可变快照逐项比较。任一不一致即派生为“检验已失效，需复检（STALE）”，旧质量记录保持原样，物流确认被拒绝。

完成后的 FAIL 或失效的 PASS 不允许原单改成 PASS。整改后创建一张关联相同当前物流单的新检验单。每个来源物流单同一时刻只允许一张活动草稿；历史完成单可有多张。门禁只采用最新的权威记录及其当前快照，因而新 PASS 可以满足门禁，历史 FAIL/PASS 仍完整保留。

## 多行门禁与原子性

一张质量单覆盖当前物流草稿的全部明细。创建时后端自动生成每个来源行的检验快照，不允许用户增删来源行。物流确认要求最新质量单：

- 状态为 `COMPLETED`；
- 结果为 `PASS`；
- 覆盖当前每一行且没有多余行；
- 每一行快照与当前来源完全一致。

缺失、草稿、取消、FAIL、STALE 或少一行均拒绝整张物流单确认，不做部分过账。校验位于采购入库/销售出库原有数据库事务内部，并在任何库存、库存流水、应收/应付、凭证、会计分录、履约累计或确认审计写入之前执行。因此拒绝时所有这些数据保持不变。

## 角色与界面

`test_warehouse`（仓库角色）拥有 IQC/OQC 查看和执行权限，可从采购入库草稿创建 IQC、从销售出库草稿创建 OQC，并完成、取消或创建复检。质量列表不提供独立新建入口。来源单号、供应商/客户、产品、规格（模型可用时）、数量、仓库和批次均只读；质量人员只填写检验日期、抽样数、合格/不合格数、结果、缺陷原因、处置和备注。

物流列表及详情公开中文派生质量状态：未检验、检验草稿、检验合格、检验不合格、检验已失效需复检。`test_sales` 和 `test_accounting` 可通过其已有物流查看权限看到相关状态，但不能执行质量；`test_reviewer` 不通过审批中心审核 IQC/OQC；管理员保留广泛可见性。

## 审计与生命周期

审计事件包括创建、更新、完成 PASS、完成 FAIL、取消和创建复检。事件带质量单 ID，摘要带来源单 ID、结果和操作者；时间戳由审计基础设施记录。来源行 ID 保存在质量明细，可与审计事件共同追溯。

草稿可取消。完成记录为不可变业务历史；被物流确认使用的 PASS 也不能通过普通业务 UI 删除。旧版未关联记录明确显示为 `LEGACY / UNLINKED INSPECTION`，仅供读取，永远不能满足新门禁。紧急清理仍属于例外的管理员数据修复流程。
