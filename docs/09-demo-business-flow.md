# Modern ERP 教师演示业务流程

本文用于课堂或验收演示，描述当前已经实现的能力，不把延期功能包装成可操作模块。系统内“业务总览”使用相同的真实页面与权限边界。

## 一、业务链

### 销售链

客户 → 销售订单 → 审批 → 销售出货 → 应收账款 → 销售折让 → 收款单 → 销售统计。

订单审批只代表业务授权。销售出货确认才扣减库存、写库存异动、确认销售收入并形成应收；销售折让针对同一正数应收原子写入负向应收调整并生成冲减凭证；收款确认核销应收并生成结算凭证。销售折让不进入审批中心，不重复生成凭证。

### 采购链

供应商 → 采购订单 → 审批 → 采购入库 → 应付账款 → 采购折让 → 付款单 → 采购统计。

采购入库确认增加库存并形成应付；采购折让针对同一正数应付原子写入负向应付调整并生成冲减凭证；付款确认核销应付并生成结算凭证。采购折让不进入审批中心，不重复生成凭证。

### 库存链

库存查询 → 库存调拨 → 库存盘点 → 库存调整 → 库存报废 → 存货月结 → 库存异动。

盘点采用草稿、提交、独立审批；调拨和调整属于执行确认，不进入订单审批队列。库存报废在确认时按仓库 + 货品原子校验库存，任一行不足整张回滚；已确认与已取消的报废单只读，不写凭证、不进入审批中心。存货月结仅 admin 可执行，结账生成只读快照（期末数量 = 当前库存 − 期末后净异动），不改库存、不写凭证；仅最近 CLOSED 期间可反结账，重结在事务内重建快照不重复行。库存异动可回到对应来源单据（包含 `INVENTORY_SCRAP` 来源过滤）。

### 生产链

BOM／制品工序标准 → 制令单 → 开工 → 用料出库 → 生产入库 → 完工。

BOM 回答“需要什么材料”，制品工序标准回答“需要经过哪些工序”；两者都是产品主数据。路线本身不改库存、不生成凭证、不进入审批。用料出库产生组件库存 OUT，生产入库产生成品库存 IN；制令单完工本身不会重复产生库存。

### 计划与物料需求链（M11 + M12）

销售订单 → 计划预测（已生效） → MRP（按销售订单 / 计划预测 / 两者叠加） → 生产建议 / 采购建议。

M11：MRP 是规划引擎，输出不可变快照建议，不创建业务单据，不改库存、不写凭证、不进审批中心。

M12：在 MRP 建议之上分出两条教师可操作链：

```
销售订单 ─┐
          ├→ 计划预测 ─→ MRP ─→ 生产建议（MAKE） ─→ 生产指令 ─→ 制令单 ─→ 用料出库 ─→ 生产入库
          └───────────────────────────────       ─→ 采购建议（BUY）  ─→ 采购指令 ─→ 请购单 ─→ 采购订单 ─→ 采购入库
```

三条新单据家族：`生产指令`、`采购指令`、`请购单`，均为规划文档：

- 生产指令 / 采购指令：`DRAFT → RELEASED → CANCELLED`；下达后才能显式生成下游；不写库存 / 凭证 / 审批；MRP 建议数量本身不变，剩余与已下达数量由后端只读计算。
- 请购单：`DRAFT → SUBMITTED → APPROVED / REJECTED → CANCELLED`；接 M3 审批中心；创建人不可自审；APPROVED 后才能生成采购订单。
- 部分下达：同一 MRP 建议可被多条指令分批下达（建议 100 = 60 + 40），剩余为 0 时第 `+1` 次下达返回 409。

### 财务结算链

销售出货／采购入库 → 应收／应付 → 收款／付款 → 会计凭证 → 财务与决策报表。

所有金额在后端使用整数分。关闭会计期间会阻止业务确认和结算确认，事务失败时不保留部分库存、子账或凭证影响。

## 二、五个演示角色

| 角色 | 演示职责 | 主要入口 | 明确不负责 |
|---|---|---|---|
| `test_admin` | 系统管理、生产主数据、盘点审批、全局查看 | 业务总览、BOM、制品工序标准、计划预测、MRP、生产指令、采购指令、请购单、制令单、用料出库、生产入库、存货月结、审批中心、全部报表、系统管理 | 无额外第六角色 |
| `test_sales` | 商务单据发起 | 客户/供应商、销售订单、采购订单、CRM、本人发起的审批 | 财务结算、生产、计划预测 / MRP、库存报废、月结、审批动作 |
| `test_reviewer` | 订单与请购单审批 | 审批中心、销售订单审批、采购订单审批、请购单审批 | 物流执行、财务、生产变更、计划预测 / MRP、库存报废、月结 |
| `test_warehouse` | 实物流与质量 | 销售出货、采购入库、退货、库存查询/调拨/盘点/异动、库存报废、IQC/OQC | 财务结算、库存调整、生产变更、计划预测 / MRP、月结 |
| `test_accounting` | 财务、结算、报表 | 会计凭证、应收、应付、收款、付款、财务报表、授权的决策报表 | 实物库存、生产变更、计划预测 / MRP、库存报废、月结 |

前端隐藏按钮或入口只是用户体验层；后端仍对每个 API 重新检查权限。注册权限保持 100，不按用户名写授权逻辑。

## 三、10–15 分钟主演示

1. `test_sales` 创建并提交销售订单。
2. `test_reviewer` 在审批中心审批销售订单。
3. `test_warehouse` 从销售订单创建销售出货并确认。
4. 展示库存减少、库存异动、销售收入凭证和应收账款来源。
5. `test_accounting` 创建收款单，先做部分收款，再结清剩余应收。
6. 展示应收余额变化和收款凭证。
7. `test_sales` 创建并提交采购订单。
8. `test_reviewer` 审批采购订单。
9. `test_warehouse` 创建并确认采购入库。
10. 展示库存增加、库存异动、采购凭证和应付账款。
11. `test_accounting` 创建并确认付款单，展示应付余额和付款凭证。
12. `test_admin` 演示 BOM／制品工序标准 → 制令单 → 开工 → 用料出库 → 生产入库 → 完工。
13. 展示生产用料 OUT、生产入库 IN 及单据关系。
14. `test_admin` 演示 计划预测 → MRP（销售订单 + 计划预测）→ 生产建议 / 采购建议；说明 MRP 输出仅为建议，不创建业务单据。
15. 打开五张决策报表，演示过滤、KPI、表格和订单下钻。
16. `test_accounting` 演示销售折让：新建 DRAFT 选同一客户的来源应收，确认后查看 Dr 6001 / Cr 1122 凭证、负向应收调整、客户净欠款下降；超出来源剩余额度的尝试 409；收款必须不超过客户净欠款（8001 → 409；8000 → 200）。
17. `test_accounting` 演示采购折让：对称 AP 行为；客户 / 供应商对账单上新增独立的 SALES_DISCOUNT / PURCHASE_DISCOUNT 调整行；后结算贷项经审批中心之外的财务流独立完成。
16. `test_warehouse` 演示库存报废：DRAFT 新建含两个仓库 + 货品的报废单，确认后查看库存减少与 `INVENTORY_SCRAP` 来源的库存异动；再新建一行数量大于库存的明细，确认返回 409 且整张单据维持 DRAFT。
17. `test_admin` 演示存货月结：执行 `2026-08` 月结（仅最近已结期间可反结账，重结不重复快照行），点击详情查看期末数量 = 当前库存 − 期末后净异动；再次反结账返回 409（已经 REOPENED），重结 200。

## 四、约 5 分钟短演示

1. 在 375px 窄屏展示移动壳、应用启动器、业务总览和审批中心。
2. 打开一张已审批销售订单，经销售出货查看库存异动与应收来源。
3. 打开对应收款单，展示部分核销或已结清状态及凭证。
4. 打开一张制令单，沿用料出库、生产入库关系查看生产追踪。
5. 打开销售统计和库存异动明细，展示 KPI、过滤与 SPA 下钻。

## 五、演示数据策略

- 开发环境沿用 `server/db.js` 中确定性的本地种子；重复启动采用幂等插入，不自动制造大量已完成业务链。
- 生产配置必须使用 `NODE_ENV=production` 且保持 `ERP_SEED_DEMO=false`。生产环境不会自动创建演示账号或业务数据。
- `pnpm reset-data` 在生产环境明确拒绝执行；不得使用任何“重置全部生产数据”脚本。
- 若需要 `test_*` 验收账号，由管理员按 `docs/demo-accounts.md` 的安全流程绑定现有五个角色；密码通过仓库外渠道提供。

## 六、范围边界与已知非阻断项

计划预测、MRP 计划建议、生产指令、采购指令、请购单作为 v1.1 M11 + M12 canonical 完成；MRP 输出不创建业务单据、不改库存、不写凭证、不进审批中心；下游单据（制令单 / 采购订单）必须由用户在 RELEASED / APPROVED 后显式触发生成。库存报废与存货月结作为 v1.1 M13 canonical 完成；销售折让与采购折让作为 v1.1 M14 canonical 完成，两者均不进入审批中心、不写重复凭证。M14 同时为结算流程引入客户级 / 供应商级净欠款安全门，杜绝「未应用预收」式贷项绕过。工作中心主档扩展、产能计划、工序级生产执行、人工／设备报工、工序级成本、销售折让配套的多税率结算、采购折让配套的多税率结算和销售 / 采购执行报表仍为 DEFERRED，不存在活动导航卡片。历史兼容 API 不等于受支持的教师 UI。

当前 Vite 生产构建可能报告单个压缩后 JS chunk 超过 500 kB。这是课程／演示规模下的非阻断性能提示，不是功能缺陷；M9 不为消除提示进行高风险架构拆分。
