# Modern ERP v1.6.1 Release Notes

V1.6.1 是基于已发布 `v1.6.0` 的 UAT 修复候选，不改变 V1.6 的 canonical 路由、审批族、权限模型或库存会计边界。

## 修复与改进

- 修复 MySQL 8 读取采购入库详情时，供应商账单关系查询因 `DISTINCT` 与非选择排序列组合而失败的问题；查询改用可移植的 `EXISTS`，保持响应字段、去重和稳定排序。
- 补齐销售出库到 OQC 的上下文工作流：创建或复检后可直达对应检验，完成后可返回来源销售出库；OQC 仍是质量门禁，库存仍仅在销售出库确认时变动。
- 在制令单执行界面公开满足报工条件后的“完成工序”动作，并展示可执行的完工阻断原因；既有工序顺序、领料、入库、期间与审计保护保持不变。
- 将 Linux x64 纳入 pnpm canonical `supportedArchitectures`，保留 Windows x64 和既有构建白名单，使 Ubuntu 22.04 可使用冻结锁文件安装 Rollup 原生包并构建。
- 为已审批请购单增加按供应商批量转换：同供应商多物料形成一张多行采购订单，不同供应商严格分单，保留行级来源、部分转换、数量上限、审批和多行入库合同。

## 兼容性与部署

- Node.js 22.23.2、React 19、Vite 7；
- SQLite 继续作为本地开发、测试和完整回归兼容路径；
- MySQL 8 继续作为一等运行后端和目标生产路径；
- Ubuntu 22.04 / Linux x64 使用 `pnpm install --frozen-lockfile` 后执行 `pnpm build`；
- Nginx + systemd 部署模型不变。

## 发布状态

本文件描述发布候选内容，不表示生产部署已经发生。`v1.6.1` tag、push 和部署均未由本次工作授权或执行；最终身份仍以 Git release tag 为准。
