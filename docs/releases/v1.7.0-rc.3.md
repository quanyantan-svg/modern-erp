# Modern ERP v1.7.0-rc.3 Release Notes

V1.7.0-rc.3 是**第三次用户测试候选版本**。它在 `v1.7.0-rc.2`（commit `c857bf0`）之上交付
**三项残余闭合**：委外库存异动的总账接线、单腿入库异动的入库价值、手工凭证守卫的受控科目族
扩展与旁路闭合。三项均已在**真实 MySQL 8 客户测试环境**上验收通过。

**本版本不是生产发布。** 手册级关闭（Manual Capability Closure）与九域 Release Readiness 仍未签发。
最终身份以 Git release tag 为准。

## 相对 v1.7.0-rc.2 的变更

### 委外库存异动的总账接线（Requirement §31.22 / Design §26.43）

委外的发料 / 补料 / 退料 / 倒冲 / 收货生效此前**只改权威估值池、不过账总账**，权威结账检查
`INVENTORY_VALUE_TO_GL` 因此恒不为 0（客户环境实测 −1600，两个委外订单各 800）。

- 新增 `server/modules/outsourcing-gl-integration.js`：委外事件 → 总账分录的**唯一**映射处。
- 分录：发料 / 补料 `借 其他存货(1406) V / 贷 物料自身存货角色 V`；退料反向；
  倒冲 `借 委外加工费(6408) V / 贷 1406 V`；收货 `借 成品存货角色 F / 贷 6408 F`。
- 发出商品取角色码 `OTHER_INVENTORY`（**不**取 `1404 在制品`：其 WIP 价值子账
  `production_order_id` 为 `NOT NULL` 外键，委外写不进去，占用 1404 会使 `WIP_TO_GL` 立即失配）。
- 总账存货角色余额与估值流水合计**逐步同域**（发料后 / 倒冲后 / 收货后 / 账单后四个时点均为 0）。

### 单腿入库异动的入库价值（Requirement §32.18 / Design §27.63）

对全部 `movementKind='IN'` 的调用点做**穷尽枚举**，得到 **5 条**「只有入库腿、没有出库腿」的
流程缺权威入库价值（此前登记 3 条，本轮补齐 2 条）：组装成品入库腿、拆卸组件回收入库腿、
步进调拨入库腿、步进调拨退回入库腿、VMI 收货入库腿。

- 新增 `server/modules/inventory-single-leg-valuation.js`：自持计值的**唯一**实现点。
- 价值来源：组件出库账面价合计 / 母件出库账面价按数量分摊 / 调出腿账面价 /
  canonical `receivePositiveSourceValue`（既有账面单价 → 冻结标准成本）。
- 组装 / 拆卸的整段位移与其自持计值改为**同一事务**，计值失败整段回滚。
- §32.17 `IW-VAL-05` 同步修订：VMI 的目标按代码现状改为「VMI 收货入库腿」（原「VMI 所有权转移」
  的写入点在代码中不存在，该路径固定 409）。

### 手工凭证守卫的受控科目族扩展与旁路闭合（Requirement §35.13 / Design §31.18）

- 新增 `server/modules/accounting-manual-voucher-guard.js`：守卫的**唯一**实现；
  受控集合扩到成本与差异族（`COGS` / 差异 / 吸收 / 委外加工费，共 10 个角色码）。
- 创建、改分录、冲销三条手工凭证写路径共用该守卫；系统凭证冲销不受约束。
- 错误码 `MANUAL_VOUCHER_CANONICAL_SUBJECT` 不变；非受控科目能力不回退。

## 已知残余（不得被描述为已消除）

1. **历史委外异动仍缺总账分录**（绝对值 −1600）：要让权威结账绝对值归零，需在**干净库**上重跑
   验收轮次，或由业务所有者就历史数据另行裁定。
2. **VMI 收货不登记 LOT / SERIAL 身份**：跟踪口径货品的入库价值无法归属到具体身份。
3. **步进调拨「退回来源仓」入库腿当前无 HTTP 路由**（zero-caller），本轮修复是预防性的。
4. **既有违规手工凭证不得再被冲销或改分录**（能力收缩；客户环境实测该类凭证为 0）。
5. 客户环境残留 AC2 虚构验收数据与本次增量取证的夹具；`ac2_*` 验收账号口令未轮换；
   客户环境尚未配置 TLS（仅 HTTP 80）与自动备份 timer。

本文件描述**用户测试候选版本**的内容，不表示生产部署已经发生，也不表示任何 Domain 达到
Release Readiness。以下事项仍然开放：

1. 三个域级 Acceptance / Capability Freeze 之外的 Manual Closure（22 本手册）与九域
   Release Readiness **未签发**；
2. 上述五项已知残余；
3. 四个库存报表端点缺少后端权限守卫（守卫口径待业务所有者裁定）；
4. 写路径授权尚未系统审计；
5. §36.17 / §32.17 Migration 风险工作包仍为 `PENDING_APPROVAL`（风险只在 upgrade 路径）。
