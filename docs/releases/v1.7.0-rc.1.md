# Modern ERP v1.7.0-rc.1 Release Notes

V1.7.0-rc.1 是**首次用户测试候选版本**（release candidate）。它在已发布 `v1.6.2` 之上累计 494 个提交，
把九个业务域的域级 Acceptance / Capability Freeze、Release Infrastructure、期间控制一致性与生产库存正确性
一次性收口，并把「route 可进入性」与「页面自身 API 可调用性」之间的矛盾提升为平台级合同。

**本版本不是生产发布。** 手册级关闭（Manual Capability Closure）与九域 Release Readiness 仍未签发；
四个库存报表端点缺少后端权限守卫；MySQL 备份 / 恢复的目标环境证据尚未取得。详见「发布状态」。

## 主要变更

### Release Infrastructure（Requirement §36.16，Design §32.16）

- `PL-RI-01` MySQL 生产备份、异机副本与恢复演练自动化（RPO 24h / RTO 4h / S3 兼容异机保存 / 季度演练）。
- `PL-RI-02` SQLite migration fail-closed 守卫：`scripts/qa/verify-migration-fail-closed.mjs`。
- `PL-RI-03` 生产依赖安全与构建依赖分层，新增供应链门禁。
- `PL-RI-04` canonical 浏览器发布门禁：5 类 canonical 角色 × 4 档宽度 × 93 条 route，
  区分 `PRODUCT_FAILURE` / `FIXTURE_FAILURE` / `CONTRACT_DRIFT` 三类失败。
- `PL-RI-05` 目标环境发布证据与 TLS 模板、preflight 零值泄漏 fail closed。
- `PL-RI-06` append-only 历史文档纠错登记与 current 门禁真实性。

### Platform 域闭合（21 项能力，Requirement §36 / Design §32）

通用工作流引擎（运行时、状态机、幂等、条件白名单、动作契约）、通用 SOD 引擎与 7 个审批决策点接线、
Organization Scope 子系统、Attachment / Notification / Numbering 三个子系统、生命周期 operator 工作面、
七个 operator 工作面与旧版审批流退役。域级 Acceptance 与 Capability Freeze 已签发。

### 期间控制一致性（R-02）

canonical 期间守卫收敛四个域的期间闸门；经营关账落实职责分离（归属字段、历史回填与关账 fail closed 判定）。
涉及域的 Requirement / Design 增补已批准并实施。

### 生产库存正确性闭合（`W10-INV-RISK-01`）

生产库存的数量守恒、来源关系与估值一致性在真实 MySQL 上取得证据。

### 部署就绪审计与修复

修复弹窗打开即进入无限渲染循环、通知重建身份导致的全量 refetch、生产启动崩溃、`X-Forwarded-For`
首段可伪造、Nginx 附件上限小于应用上限、备份 / 恢复 CLI 在 Windows 静默空操作、静态资源缺失回落
`index.html`、前后端页面不匹配 2 处，以及实体选择器 / 换货弹窗的请求放大。

### route exposure 与页面自身 API 权限一致性（平台级）

同一缺陷形态已在 Manufacturing & Quality、Sales & Customer、Inventory & Warehouse 三个域各暴露一处：
route 声明的 exposure 权限集合未覆盖页面自身依赖的 API 权限集合，于是同一后端主体被前端判定为
「可进入该 route」、又被后端判定为「无权调用该 route 加载时必调的 API」。本版本把它提升为平台级合同
`PL-EXPOSURE-01..07`（Requirement §36.18 / Design §32.18），并配套通用原语 `src/lib/routeApiAuthority.js`、
各域登记模块与机器守卫 `server/route-exposure-semantic-parity.test.js`。

### 浏览器发布门禁触控目标整改

按既有 Requirement（`manufacturing-quality` / `finance-operations` 的 ≥44px 与 Design §32.12.2）
整改 4 类低于 44px 的可点目标；整改后 canonical 门禁 5696 项判定的触控目标类失败为 0。

## 兼容性与部署

- Node.js 22.23.2、React 19、Vite 7；
- **用户测试版建议使用 SQLite 后端**：全新初始化的索引集合经离线 DDL 取证为全覆盖，
  迁移风险为零，备份使用仓库既有 SQLite 备份命令；
- MySQL 8 仍是一等运行后端与目标生产路径，但本版本**不**作为生产发布；
- Ubuntu 22.04 / Linux x64 使用 `pnpm install --frozen-lockfile` 后执行 `pnpm build`；
- Nginx + systemd 部署模型不变；
- 首个管理员必须通过 `pnpm setup-admin -- --username <name> --password <secret>` 显式创建。

## 发布状态

本文件描述**用户测试候选版本**的内容，不表示生产部署已经发生，也不表示任何 Domain 达到
Release Readiness。以下事项仍然开放，详见
[`docs/status/PROJECT_STATUS.md` §68](../status/PROJECT_STATUS.md) 与
[`docs/decisions/OPEN-BUSINESS-DECISIONS.md`](../decisions/OPEN-BUSINESS-DECISIONS.md)：

1. 四个库存报表端点（`/api/inventory-ledger`、`/api/inventory-aging`、`/api/inventory-slow-moving`、
   `/api/inventory/alerts`）缺少后端权限守卫 —— 守卫口径待业务所有者裁定；
2. 写路径授权尚未系统审计；
3. §36.17 / §32.17 Migration 风险工作包仍为 `PENDING_APPROVAL`（风险只在 upgrade 路径）；
4. 目标环境的真实 MySQL / TLS / Nginx / systemd 证据与手册级关闭、九域 Release Readiness 未签发。

最终身份以 Git release tag 为准。
