# Modern ERP v1.7.0-rc.4 Release Notes

V1.7.0-rc.4 是**第四次用户测试候选版本**。它在 `v1.7.0-rc.3`（commit `f6f335c`）之上闭合
**VMI 收货的总账对方腿**这一真实缺陷：VMI 收货此前只入存货、不过账总账，导致总账与价值子账
必然失配（客户环境实测每次收货 100,000 分），**VMI 收货流程无法通过权威结账**。

业务所有者 2026-11-18 裁定 **A —— 物权在收货时转移**（收货即确认存货与应付；消耗对称冲销）。

**本版本不是生产发布。** 手册级关闭（Manual Capability Closure）与九域 Release Readiness 仍未签发。
最终身份以 Git release tag 为准。

## 相对 v1.7.0-rc.3 的变更

### VMI 收货与消耗的总账接线（Requirement §31.23 / Design §26.44，`PRC-VGL-01..08`）

| 事件 | 分录 | 应付侧 |
|---|---|---|
| VMI 收货生效 | 借 `<该货品的存货角色>` / 贷 应付账款(2202) | `recognizeFinanceExposure(AP, DIRECT)` → FINAL 应付开项 |
| VMI 消耗 | 借 应付账款(2202) / 贷 `<该货品的存货角色>` | `applyCreditAdjustment(AP)` 冲减开项 |

- 金额一律取**实际写入权威估值流水**的价值，不取标准成本或估算值；
- 应付侧只经 Finance Operations 域的既有 canonical 原语，不直接写 `account_payables`；
- 凭证、估值流水、应付开项同事务；余额不足固定 409 `VMI_PAYABLE_BALANCE_INSUFFICIENT`，
  **不得**部分冲减；
- **能力收缩（已登记）**：VMI 收货与消耗的期间闸门扩展到应付轴（`FINANCE_AP_BILL`：应付 / 存货 /
  法定三轴），与采购入库 / 采购收货的既有口径一致。

### 交付环境的重置（2026-11-18 晚）

客户测试环境已按所有者裁定**清库重播种**：424 表 + 1 视图 + 5 触发器；演示数据（2 仓库 / 2 货品 /
1 委外供应商 / 2 委外货源 / 期初原材料 1000 件 / 1 张委外订单（下达 + 发料）/ 1 张组装单（确认））
全部经真实 API 造数，**每笔库存变动都有对应总账**；`admin` 口令沿用客户原值未改，6 个角色演示账号
口令已重置为交付用已知值。

## 已知残余（不得被描述为已消除）

1. **`D-P01` 仍未裁定**：VMI 结算窗口、结算数量口径、结算账单与付款机制仍开放；本版本只定
   「收货与消耗」两处的总账结果。`D-P01` 落地时**必须**一并处置「结算后消耗」与「消耗对方科目
   归属」两个子题（§31.23.5）。
2. **VMI 物权释放**（`transferVmiOwnership`）继续固定拒绝（`VMI_SETTLEMENT_POLICY_PENDING`）。
3. **VMI 收货不登记 LOT / SERIAL 身份**：跟踪口径货品的入库价值仍无法归属（§32.18 开放项 1）。
4. **步进调拨「退回来源仓」入库腿无 HTTP 路由**（zero-caller），其自持计值修复是预防性的。
5. **既有违规手工凭证不得再被冲销或改分录**（能力收缩；客户环境实测该类凭证为 0）。
6. 客户环境无 TLS（仅 HTTP 80）、无自动备份 timer；Manual Closure 与 Release Readiness 未签发。
