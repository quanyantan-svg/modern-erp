# V1.3 Phase 6D — 财务存货估值与关账完整性

## 范围与状态

Phase 6D 建立存货数量、价值子账、生产 WIP 和已过账总账之间的可核对链路。当前仍保留临时直接开票模型：销售出库产生应收/收入，采购入库产生应付；Sales Invoice、Supplier Bill、税、UOM、期初余额转换和迁移属于 Phase 6E。

开发迁移继续使用项目现有 SQLite 基线；本阶段不迁移 MySQL，不接触生产。

## 唯一估值政策

- `NONE`：按货品 + 仓库维护移动加权平均池。
- `LOT`：按货品 + 仓库 + 批次维护批次专属账面价值池；不同批次不混合。
- `SERIAL`：按序列号维护特定识别账面价值。
- 自制成品：按生产工单开工时冻结的标准制造单位成本资本化；NONE 进入移动平均池，LOT 进入输出批次池，SERIAL 为每个序列号分配确定性单位成本。

追踪策略默认映射为 `MOVING_AVERAGE`、`LOT_SPECIFIC_POOL`、`SPECIFIC_SERIAL`。一旦存在 POSTED 价值移动，方法不可更改；追踪策略与估值方法不兼容时失败关闭。`products.stock_quantity` 仅为遗留兼容列，产品 API 不允许写入，产品列表和库存报表从 `inventory` 汇总。

## 价值流水、余额与舍入

`inventory_valuation_movements` 是不可变权威历史，记录业务日期、货品、仓库、批次/序列号、数量增量、整数分价值增量、估值依据、来源单据/行、数量流水、工单与原冲销事件。`inventory_valuation_balances` 是事务维护的派生缓存，不是第二权威来源。

部分出库使用 `round(pool value × issue qty / pool qty)` 的确定性整数分分摊；全量耗尽必须取得池内全部剩余价值，使零数量余额严格为零分。所有出库保存实际分配金额，退回/冲销引用原事件，不按当前平均或当前标准成本重算。

迁移不会伪造历史成本。估值启用前的旧库存移动明确记录为 `LEGACY_UNVALUED`，保留旧数量业务兼容，但任何包含未解决旧移动的范围都不能通过权威存货关账。Phase 6E 负责受控期初转换。

## 采购、销售与库存控制

- 采购入库：以已审批 PO 单价计价，价值子账金额等于 Dr 存货 / Cr 应付的系统凭证金额，仓库不能输入成本。
- 采购退货：移除当前账面价值；供应商贷项仍按商业金额。差额进入 `PURCHASE_RETURN_VARIANCE`，凭证严格平衡。
- 销售出库：按 NONE/LOT/SERIAL 权威账面成本生成 Dr COGS / Cr 存货，与售价、收入和应收分离。
- 销售退货：按原销售出库分配恢复存货并冲减 COGS；LOT/SERIAL 的 HOLD 仍是公司资产。
- 调拨：价值按原金额在仓库维度间移动，公司总价值为零影响，不生成公司级存货 GL 凭证。
- 报废：按账面价值 Dr 报废损失 / Cr 存货。
- 调整与盘点：负向消耗账面价值；正向优先使用现有维度平均，缺少时使用冻结标准成本；两者均无则拒绝。盘点继续执行创建人与复核人分离，跟踪货品必须提供身份明细。

调整、报废、调拨、盘点的有效记录不可物理删除。领域冲销应保存原记录、原身份与原价值；遗留通用 cleanup 只允许 DRAFT/CANCELLED 且零业务效果记录，已确认、已过账、追踪、生产或结算记录一律拒绝。执行入口从普通启动器隐藏，分析/归档仍只读可用。

## 生产 WIP

- 用料出库：按库存账面价值贷记原材料；按工单冻结组件标准成本借记 WIP；差额进入材料价格差异。
- 生产退料：应按原领料的库存价值、标准 WIP 和材料差异成比例精确冲回，不使用当前平均。
- 工序报工：按冻结工时及工作中心人工/制造费用率吸收标准转换成本，Dr WIP / Cr 人工吸收 / Cr 制造费用吸收。setup 只在该工序首次确认报工吸收一次。
- 生产入库：按冻结标准制造单位成本 Dr 成品存货 / Cr WIP，并建立成品价值池。
- 入库冲销：移除原资本化金额并恢复同额 WIP。
- 工单完工：`production_wip_movements` 的剩余借/贷余额全部转入制造差异，完工后工单 WIP 必须为零；工序报废不另建重复报废凭证，其影响通过完工差异体现。

## 科目角色与凭证

`account_role_mappings` 将业务逻辑映射到现有或补充科目，包括 AR、AP、收入、原材料、成品、其他存货、WIP、COGS、盘盈盘亏、报废、材料价格差异、制造差异、人工/制造费用吸收、采购退货差异以及现金/银行。缺失映射时失败关闭；不依赖硬编码科目 ID。

系统业务凭证具有 `voucher_origin=SYSTEM`，与来源类型 + 来源 ID 唯一，事务内自动 POSTED、借贷平衡、不可编辑，只能由来源冲销。手工凭证保持 ACCOUNTING 创建/编辑/提交，REVIEWER 正常独立批准/驳回且创建人不得自批；ADMIN 保留应急权限但不是日常必需。手工已过账凭证可在当前开放期间创建全额反向、关联的 SUBMITTED 冲销凭证，再由独立复核人过账。

## 核对、健康检查与报表

`GET /api/system-health` 是只读、无自动修复的诊断中心。它检查价值缓存对流水、数量对估值、负值/残分、存货/WIP/AR/AP/现金银行/COGS 对 GL、旧未估值移动、系统凭证唯一性、完工工单 WIP 和期间顺序。返回 PASS/FAIL、BLOCKING 严重级别、差额、来源与解释。

报表接口：

- `/api/reports/inventory-valuation?asOfDate=YYYY-MM-DD`：按业务日期从不可变价值流水重算。
- `/api/reports/inventory-roll-forward?period=YYYY-MM`：期初 + 分类移动 = 期末，并列示 GL 差异。
- `/api/reports/wip-roll-forward?period=YYYY-MM`：材料/转换吸收、成品资本化、冲销、完工差异的 WIP 滚动。
- `/api/accounting/general-ledger?accountId=...&from=...&to=...`：仅 POSTED、期初、借贷、确定性运行余额、凭证和来源。

报表币种为 CNY，并明确 POSTED/价值流水口径。财务报表不声明税务或法定合规；税与显式账单尚待 Phase 6E。

## 期间、原子性与权限

所有财务估值库存事件同时检查业务日期所在存货期间和会计期间均为 OPEN，任何一侧关闭都在数量变更前拒绝。数量、追踪身份、价值池、价值流水、系统凭证、审计与幂等结果在同一数据库事务提交；凭证失败会回滚数量和价值。

存货先关、会计后关。存货关账要求所有 BLOCKING 存货/价值/WIP 检查通过；会计关账要求对应存货期间已关闭且健康检查无 BLOCKING FAIL。重新打开顺序相反：先会计、后存货，均要求原因并保留历史。关闭期间发现错误，在当前开放期间以关联冲销修正，不回写历史期间。

HOLD/RELEASE 需要仓库管理/库存管理写权限，`INVENTORY_VIEW` 不再授权写入。银行账户和固定资产写入要求各自 MANAGE 权限，`ACCOUNTING_VIEW` 仅查看。普通启动器隐藏旧现金日记账、票据、固定资产、通用工作流和有效数据清理；后端仍独立执行权限与安全检查。

## 已知边界

Phase 6D 仍是 Delivery → AR/Revenue、Receipt → AP 的临时直接开票模型。税、UOM 转换、Sales Invoice、Supplier Bill、2/3-way matching、受控期初余额、迁移/导入导出以及最终月结 UAT 在 Phase 6E 完成。在 Phase 6E 转换前，存在 `LEGACY_UNVALUED` 的开发/演示库只能运行兼容业务和诊断，不能宣称权威存货关账完成。
