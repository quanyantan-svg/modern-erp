# V1.3 Phase 7A — MySQL 8 Compatibility

## Scope and safety boundary

Phase 7A adds a MySQL 8 execution path for the frozen V1.3 domain model while retaining the existing SQLite path used by local development and the full regression suite. It does not add business features, contact production, or claim concurrent correctness. Real lock-contention, deadlock, race, and allocator stress belongs to Phase 7B.

Only an explicitly configured MySQL database is used. MySQL integration tests and conversion additionally require `ERP_MYSQL_TEST_ALLOW_RESET=true` and reject database names that do not contain `test`, `phase7a`, or `disposable`.

## Database architecture

The domain modules keep their established synchronous contract:

```text
V1.3 domain modules
        |
 prepare(sql).get/all/run + exec + transaction
        |
  database/dialect boundary
       / \
node:sqlite  MySqlSyncAdapter -> dedicated worker -> mysql2 -> MySQL 8
```

- SQLite driver: Node.js `node:sqlite` `DatabaseSync`.
- MySQL driver: `mysql2` using one dedicated connection owned by a worker.
- The worker bridge preserves the frozen `prepare().get/all/run`, `exec`, `isTransaction`, and `close` behavior without duplicating business implementations.
- Dialect conversion is centralized in `server/database/mysql-adapter.js`.
- Final-schema capture and MySQL DDL/bootstrap are centralized in `server/database/mysql-schema.js`.
- Configuration validation is centralized in `server/database/config.js` and fails closed.

The adapter uses one connection per database handle. `START TRANSACTION`, `COMMIT`, and `ROLLBACK` therefore cover all statements in a domain transaction. SQLite continues to use `BEGIN IMMEDIATE`; MySQL translates that boundary to a normal InnoDB transaction. Phase 7A verifies atomic success/rollback semantics only. Row-lock selection and concurrent conflict behavior are intentionally deferred to Phase 7B.

## Configuration

SQLite:

```dotenv
ERP_DB_BACKEND=sqlite
ERP_DB_PATH=/absolute/path/to/erp.db
```

MySQL 8:

```dotenv
ERP_DB_BACKEND=mysql
ERP_DB_HOST=127.0.0.1
ERP_DB_PORT=3306
ERP_DB_NAME=modern_erp
ERP_DB_USER=modern_erp
ERP_DB_PASSWORD=use-a-secret-manager
ERP_DB_SSL=false
ERP_DB_SSL_REJECT_UNAUTHORIZED=true
```

All MySQL connection fields are required. Invalid backends, ports, booleans, or missing credentials stop startup before use. Credentials are never stored in the repository.

## SQLite compatibility inventory

| Area | Classification | MySQL handling |
|---|---|---|
| `node:sqlite` / `DatabaseSync` | `SQLITE_ONLY` | Isolated behind database construction; MySQL uses `mysql2` worker adapter. |
| `PRAGMA foreign_keys`, WAL, integrity checks | `SQLITE_ONLY` | SQLite startup/tools retain them. MySQL uses InnoDB FKs, `information_schema`, and integration assertions. |
| `BEGIN IMMEDIATE` | `TRANSACTION_SEMANTICS_REVIEW_REQUIRED` | Translated centrally to `START TRANSACTION`; concurrency proof deferred to 7B. |
| `INSERT OR IGNORE` | `MYSQL_EQUIVALENT_REQUIRED` | Translated to `INSERT IGNORE`. |
| `INSERT OR REPLACE` | `MYSQL_EQUIVALENT_REQUIRED` | Translated to `REPLACE`; primary IDs are synthesized only for three legacy tables whose SQLite inserts omit nullable text PKs. |
| `ON CONFLICT ... DO UPDATE` | `MYSQL_EQUIVALENT_REQUIRED` | Translated to `ON DUPLICATE KEY UPDATE`. |
| sequence UPSERT with `RETURNING` | `MYSQL_EQUIVALENT_REQUIRED` | Dedicated transactional allocator action updates and reads `document_sequences` on the same connection. |
| `last_insert_rowid()` | `PORTABLE` for current domain | No shared V1.3 business path depends on it; adapter exposes MySQL `insertId` as `lastInsertRowid`. |
| `datetime('now')`, `date('now')` | `MYSQL_EQUIVALENT_REQUIRED` | Translated to `CURRENT_TIMESTAMP` / `CURRENT_DATE`; the connection time zone is UTC. |
| scalar SQLite `MAX(0,x)` | `MYSQL_EQUIVALENT_REQUIRED` | Translated to MySQL `GREATEST(0,x)`. |
| `COLLATE NOCASE` | `MYSQL_EQUIVALENT_REQUIRED` | Removed; schema uses `utf8mb4_0900_ai_ci`. |
| `sqlite_master`, `pragma_table_info` | `SQLITE_ONLY` | Common runtime/test metadata probes map to `information_schema`. |
| booleans stored as 0/1 integers | `PORTABLE` | Stored as `BIGINT`, retaining enforced 0/1 checks where declared. |
| JSON serialized into text columns | `MYSQL_EQUIVALENT_REQUIRED` | `*_json` columns use MySQL `JSON`; mysql2 returns JSON strings to preserve domain parsing behavior. |
| integer cents | `PORTABLE` | SQLite `INTEGER` maps to signed `BIGINT`; application safe-integer validation remains authoritative. |
| quantity `REAL` | `MYSQL_EQUIVALENT_REQUIRED` | Maps to `DECIMAL(24,6)`; smoke tests compare exact expected quantities and conversion totals. |
| `CHECK` constraints | `MYSQL_EQUIVALENT_REQUIRED` | Final SQLite checks are extracted and emitted as enforced MySQL 8 checks. |
| foreign keys | `MYSQL_EQUIVALENT_REQUIRED` | Rebuilt as InnoDB FKs with matching update/delete actions. |
| `AUTOINCREMENT` | `MYSQL_EQUIVALENT_REQUIRED` | Maps to `AUTO_INCREMENT` when present. Current business IDs remain explicit UUID/text IDs. |
| partial unique indexes | `MYSQL_EQUIVALENT_REQUIRED` | Implemented with nullable generated SHA-256 identity columns plus unique indexes. |
| expression/very-wide unique indexes | `MYSQL_EQUIVALENT_REQUIRED` | Implemented with generated SHA-256 identity columns, preserving NULL identity semantics. |
| strict `GROUP BY` | `MYSQL_EQUIVALENT_REQUIRED` | Manufacturing capacity grouping now names all selected nonaggregates and remains valid on SQLite. |
| NULL sorting/comparison | `PORTABLE` for accepted flows | Shared flows use explicit predicates/COALESCE; no acceptance result relies on backend-default NULL ordering. |

SQLite-specific backup, restore, reset, and legacy migration utilities remain intentionally SQLite-only. They are not shared MySQL business paths and are not presented as MySQL maintenance tools.

## Schema and constraint parity

Fresh MySQL bootstrap captures the fully migrated V1.3 SQLite schema through Phase 6E and emits the complete InnoDB schema. A `mysql_backend_metadata` completion marker is written only after tables, seeds, indexes, generated uniqueness columns, and constraints succeed. A non-empty database without that marker is rejected as partial; a marked database missing expected tables is also rejected.

The current bootstrap contains 172 domain tables plus one MySQL completion metadata table. Bootstrap is repeatable on a completed schema and replays static seeds with `INSERT IGNORE`.

- IDs and indexed text are `VARCHAR(128)`, sufficient for current UUID/document identifiers and bounded to support InnoDB compound keys.
- Descriptive text remains `LONGTEXT`.
- Integer cents and integer counters use `BIGINT`.
- Quantities/rates use `DECIMAL(24,6)`.
- `*_json` fields use native `JSON`, returned as strings for application parity.
- PK, FK, unique, check, nullable, and default metadata is derived from the final SQLite schema.
- Partial/expression uniqueness uses deterministic generated digests rather than weaker application-only checks.

Historical SQLite migrations are unchanged and continue to build/upgrade SQLite databases. MySQL deliberately bootstraps the final frozen model rather than replaying SQLite DDL.

## Document sequences

`document_sequences` does not use MySQL `MAX`/`COUNT` allocation. The MySQL adapter performs the upsert and reads the allocated value on the same connection and inside the caller transaction. `document_number_allocations.idempotency_key` remains unique.

Phase 7A proves sequential allocation (`00001`, `00002`), idempotent replay, uniqueness, and rollback. Heavy concurrent allocation stress is Phase 7B.

## SQLite to MySQL conversion rehearsal

Run only with a disposable, current V1.3 SQLite source outside the repository database path:

```powershell
$env:ERP_DB_BACKEND='mysql'
$env:ERP_DB_HOST='127.0.0.1'
$env:ERP_DB_PORT='3306'
$env:ERP_DB_NAME='modern_erp_phase7a_test'
$env:ERP_DB_USER='modern_erp_test'
$env:ERP_DB_PASSWORD='<secret>'
$env:ERP_MYSQL_TEST_ALLOW_RESET='true'
node scripts/convert-sqlite-to-mysql.mjs --sqlite C:\temp\synthetic-v13.db
```

The converter:

1. refuses `data/erp.db`, relative sources, non-disposable target names, and missing reset opt-in;
2. requires SQLite integrity and FK checks to pass;
3. requires the complete source table set to exist in the bootstrapped target;
4. rejects NULL primary keys instead of silently coercing them;
5. copies rows with FK enforcement disabled only for load ordering, then restores it;
6. compares every table row count and every primary/source ID set;
7. compares integer-cent and quantity controls for inventory, valuation, AR/AP, vouchers, WIP, invoices, bills, tax, UOM-adjacent documents, and opening data;
8. fails on the first mismatch.

The automated rehearsal uses synthetic data only.

## MySQL test gate

Create an empty disposable MySQL 8 database and grant the test user full rights only on that database. Then set the five `ERP_DB_*` MySQL fields plus:

```dotenv
ERP_MYSQL_TEST_ALLOW_RESET=true
```

Run:

```sh
pnpm test:mysql
```

The command refuses a database name without `test`, `phase7a`, or `disposable`. It runs the fresh bootstrap/transaction/sequence gate, SQLite conversion rehearsal, and identical MySQL domain contracts for:

- purchase receipt, IQC, supplier bill, GRNI and AP;
- sales delivery, OQC, invoice, AR, COGS and tax;
- settlement and commercial credit;
- LOT/SERIAL, holds, genealogy, and trace;
- material issue, routed execution, WIP and finished-goods receipt;
- valuation and system vouchers;
- System Health;
- Go-Live, inventory close, accounting close, and late-posting refusal.

If configuration is absent, the command exits nonzero with `MYSQL TEST ENVIRONMENT = UNAVAILABLE`; it never reports a skipped suite as a pass.

SQLite remains gated separately:

```sh
pnpm test
pnpm build
```

## Rollback boundaries and known limitations

- No production database is contacted or converted by Phase 7A tooling.
- MySQL bootstrap is intended for an empty database or an already completed Phase 7A schema. A partial/unmarked schema is rejected, not repaired in place.
- Conversion replaces data only inside an explicitly opted-in disposable target and cannot be used against the repository SQLite database.
- SQLite backup/restore/reset scripts remain SQLite-specific.
- The synchronous worker bridge caps a single serialized result at 16 MiB; large exports should be streamed in a later infrastructure phase.
- TLS supports the current boolean/reject-unauthorized controls. Certificate/key file plumbing is intentionally deferred until an environment requires it.
- Phase 7A validates correct transaction semantics, not concurrent safety. Row locking, deadlock retry, multi-process sequence contention, and race stress are Phase 7B acceptance items.
