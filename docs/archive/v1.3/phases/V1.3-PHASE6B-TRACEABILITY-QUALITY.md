# V1.3 Phase 6B：批次 / 序列号追溯与可配置质量控制

## 1. 范围与不变量

Phase 6B 在现有 `inventory` 与 `inventory_transactions` 数量总账上增加物理身份维度，不建立第二套产品/仓库总库存。历史货品默认 `NONE`，历史流水明确保持“未跟踪”，系统不补造批次、序列号或生产谱系。

规范角色仍为 ADMIN、SALES、REVIEWER、WAREHOUSE、ACCOUNTING 五个；审批中心仍只有 SALES_ORDER、PURCHASE_ORDER、INVENTORY_CHECK、ACCOUNTING_VOUCHER、PURCHASE_REQUISITION 五类。HOLD/RELEASE 与 QCP 配置是领域动作，不是新审批族。

## 2. 跟踪策略

| 策略 | 用户标签 | 约束 |
|---|---|---|
| `NONE` | 不跟踪 | 沿用数量库存 |
| `LOT` | 批次管理 | 每次库存移动必须分配权威 lot ID；一批可有多件并跨仓移动 |
| `SERIAL` | 序列号管理 | 每个物理单位一个权威 serial ID；选择数必须等于数量 |

`NONE → LOT/SERIAL` 只允许在公司库存为零、没有相关库存草稿、没有跨越变更点的活动生产执行时发生。第一次跟踪流水产生后，`LOT ↔ SERIAL` 和 tracked → `NONE` 均拒绝。每次设置写入 `product_tracking_policy_history`，保存操作者、原因与生效时间。

## 3. 批次、序列号、可用性与保质期

批次由 `(product_id, lot_code)` 唯一识别，保存生产日期、失效日期、供应商批号及创建来源。序列号由 `(product_id, serial_number)` 唯一识别，保存当前仓库与 AVAILABLE、HOLD、CONSUMED、DELIVERED、SCRAPPED 生命周期状态；正常业务从不删除并重建身份。

```text
SERIAL inbound → AVAILABLE ─┬→ CONSUMED（生产领用）
                            ├→ DELIVERED（客户交付）
                            ├→ SCRAPPED（报废，终态）
                            └→ HOLD → RELEASE → AVAILABLE
                                     ↑
                          销售退货默认进入 HOLD
```

ON HAND 是物理在库总量，包含 HOLD；AVAILABLE 排除 HOLD、过期、已领用、已交付、已报废身份。日期判定采用 `business_date > expiry_date`，不会由后台任务改写状态。生产日期与 `shelf_life_days` 可确定失效日期时自动预填。HOLD 与 RELEASE 均要求原因并永久保存操作历史。

## 4. 库存维度与 CHECK-only 对账

LOT 产品必须满足：

```text
inventory(warehouse, product).quantity
  = SUM(inventory_lot_balances.quantity)
```

SERIAL 产品必须满足：

```text
inventory(warehouse, product).quantity
  = COUNT(serial WHERE lifecycle_state IN (AVAILABLE, HOLD))
```

收货、领料、生产入库、出货、退货、调拨、报废、调整和盘点在同一个 SQLite 事务中更新规范库存与身份维度。`tracked_inventory_movements` 是 `inventory_transactions` 的身份扩展明细，保存来源单/来源行、业务日期和 lot/serial ID。`GET /api/tracking/reconcile` 仅报告差异，绝不修复；启动迁移也不修复。

## 5. 采购、生产与销售身份流

```text
PO → Purchase Receipt DRAFT
       ├─ LOT：一行可显式拆多个批次，合计必须等于行数量
       └─ SERIAL：每件一个序列号，数量必须完全相等
            ↓ 身份快照
          IQC PASS / 显式 QCP WAIVER
            ↓ 原子过账
 canonical inventory + identity dimension + identity movement + AP/voucher
```

LOT 采购收货复用同产品同批号的权威身份，不创建重复批次。SERIAL 正常收货拒绝任何既存序列号；只有显式、来源匹配的退货路径能恢复既有身份。

生产领料必须选择同货品、同仓库、AVAILABLE、未 HOLD、未过期的批次/序列号。批次可拆分领料；序列号必须逐件选择。生产入库的 LOT 成品显式指定输出批次，SERIAL 成品为每件创建唯一身份。

销售出货以同样规则选择确切身份，OQC 冻结选择集合。出货后 SERIAL 成为 DELIVERED，并连接销售出货、销售订单和客户。销售退货只能选择来源出货实际交付且尚未退回的身份，确认后进入 HOLD；采购退货只能移除来源收货带入且当前仍实际在库的身份。

调拨移动确切批次数量或序列号位置，公司总量不变；普通调拨排除 HOLD。报废需要确切身份，SCRAPPED 序列号永久不能正常使用。正调整必须创建/指定身份，负调整必须选择现有身份。LOT 盘点按批次，SERIAL 盘点按明确的在场/缺失序列号；库存盘点仍由仓库提交、REVIEWER 审批，审批是唯一库存影响点。

## 6. 生产谱系

`production_genealogy_allocations` 以结构化外键连接：

```text
input lot / serial
  → material issue item
  → production order
  → production receipt
  → output lot / serial
  → sales delivery / customer
```

LOT 输入的活动分配总量不能超过该工单净确认领用量；SERIAL 输入默认只能分配一次。精确成品序列号追溯只有在对应分配真实存在时才成立，不会由 BOM 比例推断。物料退回上限为原领用量减去仍支撑活动成品谱系的数量。生产入库冲销把相应谱系标为 REVERSED 而不删除历史；LOT 部分冲销采用显式输出身份分配，SERIAL 按确切成品身份冲销。

向前追溯从组件身份返回采购来源、供应商、领料、生产工单、成品身份、客户交付。向后追溯从成品身份返回当前位置、生产入库、工单、组件身份、组件来源和质量证据。影响查询同时列出相关成品的在库与已交付状态，只读且不自动创建召回、退货或财务单据。

## 7. QCP 解析、豁免与版本快照

Phase 6B 只支持 PURCHASE_RECEIPT 与 SALES_DELIVERY 两个操作点，以及 GLOBAL 与 PRODUCT 两级作用域：

```text
有效产品规则
  ↓ 无匹配
有效全局操作默认
  ↓ 缺失/异常
FAIL-SAFE REQUIRED + FULL sampling
```

迁移创建来料与出货两个 REQUIRED/FULL 全局默认，保持 Phase 3 行为。缺少规则永远不代表免检。产品免检必须是 ADMIN 创建的显式 `inspection_required=false` 版本，填写原因、版本和生效日期；WAREHOUSE/SALES 无权临时绕过。

物流草稿按每一行冻结 `logistics_quality_policy_snapshots`：QCP ID、版本、是否必须检验、抽样方式、抽样参数及免检原因。之后修改 QCP 不改变既有草稿。确认使用的免检快照可审计。

## 8. 检验标准、抽样与身份快照

QCP 标准支持 PASS_FAIL、NUMERIC、TEXT。创建 IQC/OQC 时复制到 `inspection_criteria_snapshots`；完成后结果不可变。必填 PASS_FAIL 必须有 PASS/FAIL，必填 NUMERIC 必须是数字且处于可选 min/max 内，必填 TEXT 必须非空；任一必检项不满足时拒绝总体 PASS，FAIL 保留证据。

抽样规则：FULL = 来源数量；FIXED_QUANTITY = `min(配置数, 来源数)`；PERCENTAGE = `min(来源数, max(1, ceil(来源数 × 百分比 / 100)))`。零、负数和百分比大于 100 的配置拒绝激活。

IQC/OQC 同时冻结仓库、产品、数量与排序后的批次/序列号集合。数量、仓库、lot/serial 选择任一改变都会使原检验成为 STALE。IQC FAIL 不增加库存、AP 或凭证；OQC FAIL 不减少库存、不改变序列号状态。有效 PASS 只允许一次幂等过账。

## 9. API 与界面

- `PATCH /api/products/:id/tracking-policy`：安全变更跟踪策略。
- `PUT /api/tracking/allocations`：保存草稿来源行的身份分配。
- `POST /api/tracking/:type/:id/hold`：HOLD/RELEASE。
- `GET /api/tracking/reconcile`：CHECK-only 对账。
- `POST /api/production-genealogy`：权威谱系分配。
- `GET /api/traceability`：向前/向后追溯及影响信息。
- `GET|POST /api/quality-control-points`：ADMIN 查看/创建版本化 QCP。

产品页使用“不跟踪 / 批次管理 / 序列号管理”和“保质期（天）”中文设置。追溯页采用移动优先卡片链，明确区分身份、当前位置、库存移动、生产谱系与客户交付。

## 10. 幂等、期间与遗留限制

Phase 6A 的持久化幂等记录覆盖采购收货、销售出货、生产领料和生产入库；身份创建、余额变化与谱系写入均在同一业务事务内，成功重试返回原业务结果而不重复维度效果。关闭库存/会计期间的既有门禁继续在身份过账之前执行，跟踪身份不能绕过期间控制。

旧 `NONE` 流水只展示“历史记录：未启用批次/序列号管理”。没有权威谱系分配时界面显示“没有权威谱系分配”，绝不声称精确单位来源。
