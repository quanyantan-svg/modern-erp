# V1.3 Phase 6E — 商业计费、税、UOM 与 Go-Live

## 范围与权威链路

Phase 6E 在 Phase 6D 的库存价值流水、系统凭证、往来子账和健康检查上增加商业单据层，不建立第二套财务或库存系统。销售权威链路为 `Sales Order → Sales Delivery → Sales Invoice → AR / Revenue / Output Tax`；采购权威链路为 `Purchase Order → Purchase Receipt → GRNI → Supplier Bill → AP / Input Tax`。

在 `SEPARATE` 模式下，Delivery 确认只改变库存、估值和 COGS；Receipt 确认只借记存货、贷记 GRNI。Invoice/Bill 过账才生成 AR/AP 和相应税额。Invoice 支持同客户多个 Delivery 行合并、分次开票和累计不超交付数量；Bill 支持分次计费、PO/Receipt/Bill 三单匹配和累计不超收货数量。供应商发票号按供应商唯一。未匹配的发票可以为 `WAITING_MATCH`，但不能过账。

`DIRECT_BILL` 和 `AUTO_BILL` 是兼容模式：确认 Delivery/Receipt 时在同一事务内创建并过账链接的 Invoice/Bill，权威计费记录仍是 Invoice/Bill。未显式传入新模式的旧 API 客户端保留 `LEGACY_DIRECT`，历史 Delivery 型 AR 与 Receipt 型 AP 只做兼容读取和核对，不是新流程来源。新 UI 默认显式发送 `SEPARATE`。

Sales Credit Note 和 Supplier Credit Note 必须链接已过账 Invoice/Bill，按原单净额/税额比例精确冲回并通过现有贷项应用链路冲减开放项。物理退货仍负责库存与 COGS；商业退货/折让由 Credit Note 负责。

## GRNI、三单匹配和价差

Receipt 按已批准 PO 冻结价格计入存货和 GRNI，不因后续账单价格改写收货估值。Supplier Bill 过账借记 GRNI 和 Input Tax，账单净额与已收货价值的差额进入 `PURCHASE_PRICE_VARIANCE`，贷记 AP。核心角色是 `GRNI`、`INPUT_TAX_RECEIVABLE`、`ACCOUNTS_PAYABLE` 和 `PURCHASE_PRICE_VARIANCE`。

## 税

税码按 code + version 管理名称、有效日期、启用状态与有理数税率。单据支持 `NO_TAX`、`EXCLUSIVE` 和 `INCLUSIVE`。每行使用整数分和整数分子/分母计算，以 half-up 得到行税额；单据税额始终等于行税额之和。过账时冻结税码、版本、税率、净额、税额和含税额，不追溯重算。健康检查对账 `OUTPUT_TAX_PAYABLE` / `INPUT_TAX_RECEIVABLE` 与 GL。本功能不声明法定税务、政府电子发票或申报合规。

## UOM

产品保存权威 `base_uom_code` 及可选采购/销售 UOM。产品换算使用有效日期和版本的精确 numerator/denominator，例如 `1 BOX = 10 EA`。商业单据行和 BOM 行冻结文档 UOM、文档数量、换算比及 base quantity；库存、生产和计划始终使用 BASE UOM。SERIAL 换算后的 base quantity 必须是整数。历史行使用已冻结快照，不因主数据新版本重解释。

## 期初与 Go-Live

`Opening Batch` 严格按 `DRAFT → VALIDATED → SUBMITTED → APPROVED → POSTED` 转换，内容可包含存货数量/价值、LOT/SERIAL 标识、AR、AP、现金/银行和期初试算。校验要求行类型与引用完整、借贷平衡且 System Health 无阻断 FAIL。ACCOUNTING 编制/提交，REVIEWER 审批/过账，创建人不得自批或自行过账。合法批次在一个事务中过账；`Activate` 后期初入口永久锁定。生产期初不使用 seed/reset 或 `products.stock_quantity`。Opening WIP 迁移暂不支持。

## 导入、导出和编号

CSV 导入实行 `UPLOAD/STAGE → VALIDATE → PREVIEW → COMMIT`；预览只读，错误按行返回，任何行失败都禁止提交，提交使用单一事务和幂等键。最小数据集为 customers、suppliers、products、UOM/conversions、warehouses 和 opening balance。标准导出包含存货数量/价值、AR/AP 开放项、GL 明细、税摘要和 System Health。

关键商业单据使用 `document_sequences` 事务更新，分配结果与幂等键唯一绑定。号码可有空洞但不允许重复，重试返回原号码；不使用 `COUNT(*)+1` 或非安全 `MAX+1`。SQLite 为当前受测实现，MySQL 并发压力留待 Phase 7。

## MRP 与月结

`SALES_PLUS_FORECAST` 在同一次运算的产品桶采用 `MAX(已批准 SO 未交需求, 有效 Forecast)`，不盲目相加。可用库存排除 HOLD 和已过期 LOT/SERIAL。开放供应只计已批准 PO 未收数量与 PENDING/IN_PROGRESS 生产工单未入库数量，Instruction/PR/PO 链不重复累加，已完成/取消为零。MRP 重跑删除当次派生结果后重建，不重复短缺。

月结顺序保持 `System Health PASS → Inventory Close → Accounting Close`。Invoice、Bill、Credit Note、Opening 和其他财务库存事件均在变更前检查业务日期的存货/会计期间，已关期间拒绝过账。

## 核对与明确边界

只读核对覆盖 Invoice → AR → GL、Bill → AP → GL、Receipt GRNI → GL GRNI、Output/Input Tax → GL、文档 UOM → base quantity 以及 SERIAL base quantity → serial count。检查只报告差异，绝不自动修复。

## 明确不支持（显式声明）

- **多币种**：所有金额使用单一 CNY 整数分；不维护币种表、汇率或外币重估；
- **Opening WIP 迁移**：期初批次支持 AR/AP/库存/现金，但不支持把已有生产在制迁移到 Opening Batch；新建工单仍按 BOM 投产标准成本吸收；
- **法定税务 / 政府电子发票**：税码、税率、含税/不含税、税额四舍五入到整数分；不做税务申报、增值税专票/普票签发、底账对碰或任何监管合规；
- **高级 / 里程碑开票**：不支持按里程碑、累计进度、保留金或条件触发；本阶段只有按数量和单价的常规开票；
- **APS、完整 MES/QMS**：MRP 仍只输出建议；工序级执行、设备、物料防错、SPC 流程不在本任务范围。

## 兼容与遗留

`LEGACY_DIRECT` 是 Phase 6E 引入的兼容标记；老库中没有任何 `SALES_INVOICE` / `SUPPLIER_BILL` 链接的 Confirmed Delivery/Receipt 自动保留此标记并继续按 Phase 6D 直接开票路径写 AR/AP。System Health 显式区分 `OUTPUT_TAX_TO_GL`、`INPUT_TAX_TO_GL`、`UOM_DOCUMENT_TO_BASE`、`SERIAL_BASE_QUANTITY_INTEGER`，以便新流程启用时逐项核对而不会误改历史。

未显式传入新模式的旧 API 客户端保留 `LEGACY_DIRECT`。新 UI 默认 `SEPARATE`。Phase 7 之前不会把遗留直接开票迁移为权威 Invoice/Bill；只在审计或对账时读取。
