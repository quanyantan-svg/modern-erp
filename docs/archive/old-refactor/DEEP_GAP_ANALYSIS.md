通过分析原系统的反编译BLL源代码和ASPX页面，发现以下关键差异：

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 会计科目管理（SYS_Acct）— 重大差异
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【原系统】使用zTree树形结构，30+个字段：
  ┌─ 资产类 (parent_no='0')
  │  ├─ 流动资产 (parent_no='1000')  
  │  │  ├─ 库存现金 (Acct_No='1001')
  │  │  │  ├─ Cash_IF=1（现金科目）
  │  │  │  ├─ Cury_Case（核算币别）
  │  │  │  ├─ Acct_DC（借贷方向）
  │  │  │  └─ Stop_Date（停用日期）
  │  │  └─ 银行存款 (Acct_No='1002')
  │  │     ├─ Credit_IF=1（银行科目）
  │  │     └─ ...
  │  └─ ...
  └─ ...

  关键字段：Parent_No(上级科目) | Acct_No(科目编号) | Acct_Sht(简码)
  Acct_Name(名称) | Acct_ENam(英文) | Acct_DC(借贷方向)
  Cury_Case(币别) | Cash_IF(现金) | Credit_IF(银行)
  Adjust_IF(调汇) | Stop_Date(停用) | DeptID(部门)
  Inv_IF(存货) | Offset_IF(抵销) | assist_ID(辅助核算)
  multi_firm/multi_dept/multi_staff(多维度核算)
  quanamt_IF(数量核算) | ProTo_IF(预算控制)

  【新系统】仅实现6个字段的平面表格，差距巨大。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. 凭证管理（GLS_VocA）— 重大差异
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【原系统】凭证包含表头+表体(分录)的明细结构：
  表头: 凭证号/日期/附件数/制单人/审核人/过账人
  表体: 科目编号/摘要/借方金额/贷方金额/币别/汇率/数量/辅助核算

  【新系统】仅实现简单列表展示，无凭证录入功能

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
3. 采购/销售订单 — 表单字段差异
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【原系统采购订单】每个单据20+字段：
  表头: 订单号/供应商/日期/部门/业务员/币别/汇率/备注
  表体: 行号/物料编号/品名/规格/数量/单价/金额/交期/税率
  
  【新系统】简化到5-8个字段

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
4. 应收/应付管理（ARS/APS）— 功能差异
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【原系统】完整的应收应付生命周期管理：
  应收: 应收单→收款核销→账龄分析→坏账计提→对账单
  应付: 应付单→付款核销→账龄分析→预付管理

  【新系统】仅展示应收/应付汇总列表，无核销、账龄等功能

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
