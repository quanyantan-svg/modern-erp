# V1.3 Phase 1 流程完整性契约

## 范围

本阶段只建立金额、角色、业务日期和商业单据的基础契约。审批中心仍只有 `SALES_ORDER`、`PURCHASE_ORDER`、`PURCHASE_REQUISITION`、`INVENTORY_CHECK`、`ACCOUNTING_VOUCHER` 五类。

Phase 0 的测试数据库隔离契约继续有效：测试只使用系统临时目录中的一次性 SQLite 数据库，不得访问仓库 `data/erp.db`。

## 五角色矩阵

| 角色 | 职责 | 明确禁止 |
|---|---|---|
| ADMIN | 系统/主数据配置、MRP 与计划、采购/生产指令、异常管理权限、现有五角色模型中的凭证审批 | 仍受制单人不得审批自己单据的 SoD 约束 |
| SALES | 客户/供应商、CRM，销售订单、请购单、采购订单的建立/编辑/提交 | 审批、库存执行、出入库/退货确认、调拨、用料出库、生产入库、MRP/生产计划、会计 |
| REVIEWER | 销售订单、请购单、采购订单、库存盘点的独立审批；读取支撑资料 | 普通交易创建；不得审批自己创建的单据 |
| WAREHOUSE | 采购入库、销售出库、实物退货、IQC/OQC、用料出库、生产入库、库存调整/调拨/报废、盘点创建与提交 | MRP/生产计划、会计、自己盘点单的审批 |
| ACCOUNTING | AR/AP、销售/采购折让、收付款、凭证建立/提交、财务报表 | 库存执行、MRP/制造、自己凭证的审批 |

## 金额契约

- 用户界面一律以元录入和展示，使用共享的 `YuanField` 与 `src/lib/money.js` 边界转换。
- API 和数据库一律使用安全整数分。小数分、NaN、无穷值不得进入过账边界。
- `2000` 元转为 `200000` 分，`1234.56` 元转为 `123456` 分，重新显示分别为 `¥2,000.00` 和 `¥1,234.56`。
- 销售/采购订单、请购估价、入出库、退货、折让、收付款、现金日记账、银行、票据和手工凭证均遵守该边界。

## 销售订单契约

新 V1.3 销售订单包含订单日期、要求交期、客户、收货联系人/电话/地址快照、付款条件快照、明细数量/单价/金额、合计和备注。提交前必须具备订单日期和要求交期，要求交期不得早于订单日期，每行数量和单价必须大于零。

快照在创建时可从客户主数据预填，保存后归单据所有；后续修改客户主数据不会改写订单快照。

## 请购与采购订单契约

请购单使用独立的请购日期和要求到货日，参考单价在 UI 中以元表示，在 API/数据库中为整数分。产品参考采购价可预填，草稿期间可修改，也允许暂无估价。

已审批请购单生成 PO 草稿时，现有估价原值复制；无估价时保留零价草稿，PO 必须录入大于零的最终成交价才能提交。

PO 包含订单日期、预计交期、供应商、联系人/电话/地址快照、付款条件、明细单价/金额、合计和备注。预计交期不得早于订单日期。供应商主数据的后续变更不得改写已保存 PO 快照。

## MRP 日期契约

已审批销售订单的 MRP 需求日只取 `requested_delivery_date`。新 V1.3 行不得回退到 `created_at`、`submitted_at` 或 `reviewed_at`。

为可读取升级前的历史数据，仅当 `requested_delivery_date` 和 `order_date` 都为空时，允许按工作流时间戳读取兼容日期。该兼容分支不会伪造或回填历史合同日期。

采购/生产日期语义保持明确：采购指令使用现有 `planned_date`/明细 `need_by_date`，生产指令使用现有 `planned_date`/明细 `need_by_date`，生产工单使用 `planned_start` 与 `planned_finish`；不把建立/提交时间当作业务日期。

## 会计凭证基础契约

- `test_accounting` 使用 `VOUCHER_SUBMIT` 创建、修改和提交手工凭证，仅有查看权限不意味着可创建。
- 分录金额必须为正的安全整数分。
- 借方合计必须与贷方合计完全相等，不存在 1 分容差。
- 制单人不得审批自己的凭证；当前五角色模型中由有权 ADMIN 审批/过账。

## 迁移策略

`server/migrations/v13-phase1-contracts.js` 以可重复执行的增量方式新增 SO/PO 日期与快照字段、PR 请购日期和日期索引，并对旧库的四个非管理员角色权限进行幂等对账。历史行的新业务日期保持可空，不从工作流时间伪造合同日期；新单据的提交完整性由应用层强制。

## 明确延后

- Phase 2：IQC/OQC 完整流程重设计。
- Phase 3：用料出库、生产入库及其来源链路的进一步完整化。
- Phase 4：AR/AP 未结项和结算分配模型重设计。
- Phase 5：MySQL 迁移、生产数据迁移和生产切换。

本阶段未增加税、币种、到岸成本复杂度，也未增加第六个常规角色或新的通用审批类型。
